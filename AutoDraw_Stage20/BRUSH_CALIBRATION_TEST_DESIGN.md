# Проектирование теста калибровки доски и кистей

**Статус:** проектирование; реализация ещё не подтверждена.  
**Ветка:** `feature/image-geometry-optimization`.  
**Цель:** подготовить отдельный интерфейс калибровки, в котором координаты каждой кнопки, каждой точки выбора кисти и каждой измеряемой области задаются независимо и сохраняются в профиле.

## 1. Основной принцип интерфейса

Не использовать одну общую кнопку «Настроить координаты». У каждого элемента должна быть собственная строка с собственным действием **«Задать координаты»**, статусом настройки, отображением текущих значений и кнопкой проверки.

Координаты кликов и координаты областей — разные типы данных:

- **Точка** `(x, y)`: для кнопки очистки, выбора размера кисти и других действий по клику.
- **Прямоугольник** `(x, y, width, height)`: для доски и полоски ресурса/краски.
- **Диапазон/набор точек**: для ползунка размера кисти, если используется расширенный режим.

Нельзя подменять координату кнопки прямоугольником области или наоборот.

## 2. Список независимых элементов калибровки

| Ключ профиля | Элемент интерфейса | Тип | Как задаётся |
|---|---|---|---|
| `clear_board` | Кнопка «Очистить доску» | Точка клика | Отдельная кнопка «Задать координаты»; пользователь указывает центр кнопки |
| `brush_1` | Выбор кисти 1 в расширенном режиме | Точка клика/позиция ползунка | Отдельная кнопка; нужна только если режим действительно позволяет выбрать 1 кликом или в профиле фиксируется позиция ползунка |
| `brush_7` | Пресет кисти 7 | Точка клика | Отдельная кнопка |
| `brush_14` | Пресет кисти 14 | Точка клика | Отдельная кнопка |
| `brush_20` | Пресет кисти 20 | Точка клика | Отдельная кнопка |
| `brush_slider_min` | Край ползунка, соответствующий минимальной кисти | Точка | Отдельная кнопка |
| `brush_slider_max` | Край ползунка, соответствующий максимальной кисти | Точка | Отдельная кнопка |
| `brush_slider_track` | Рабочая линия ползунка (опционально) | Отрезок/две точки | Отдельная кнопка; вычислять промежуточные значения можно только после проверки поведения слайдера |
| `board_area` | Область самой доски | Прямоугольник | Отдельная кнопка «Задать область доски»; пользователь задаёт два противоположных угла |
| `paint_meter_area` | Область полоски ресурса/краски | Прямоугольник | Отдельная кнопка «Задать область полоски краски»; два противоположных угла |
| `brush_value_area` | Текст/индикатор текущего размера кисти, если он есть | Прямоугольник, необязательный | Отдельная кнопка; использовать для OCR/проверки только если индикатор реально присутствует |
| `editor_open` | Кнопка открытия редактора, если тест сам открывает окно | Точка, необязательный | Отдельная кнопка |
| `save_drawing` | Кнопка сохранения, если тест проверяет сохранение | Точка, необязательный | Отдельная кнопка; не нажимать автоматически в обычных тестах расхода |

Если доступен только обычный интерфейс с пресетами 7/14/20, поля `brush_slider_min`, `brush_slider_max` и `brush_slider_track` остаются необязательными. Не показывать их как обязательные для запуска такого теста.

## 3. Предлагаемый вид страницы

### Блок A — кнопки и точки клика

Каждая строка содержит:

- название элемента;
- кнопку **«Задать координаты»**;
- текущие координаты `X, Y` или статус «Не задано»;
- кнопку **«Проверить клик»**;
- индикатор: «Не задано», «Задано», «Проверено»;
- при необходимости — кнопку «Сбросить».

Строки должны быть независимыми. Настройка координат кисти 14 не должна менять координаты кистей 7 и 20.

### Блок B — области

Отдельные строки для:

1. **Области доски** — прямоугольник с координатами `X, Y, ширина, высота`.
2. **Области полоски краски** — прямоугольник для снимка и анализа заполнения.
3. **Области значения кисти** — необязательный прямоугольник для числового индикатора, если он имеется.

Для каждой области нужны отдельные кнопки «Задать область», «Показать/проверить» и «Сбросить». При задании области интерфейс должен показать рамку поверх текущего экрана или снимка, чтобы пользователь мог визуально проверить, что область выбрана правильно.

### Блок C — параметры среды

Записывать для диагностики, но не предлагать как координаты кнопок:

- разрешение экрана;
- размеры окна браузера и положение окна, если доступны;
- масштаб страницы браузера;
- масштаб Windows/DPI, если надёжно определяется;
- логический размер доски движка: 460×240;
- дату и версию профиля.

Если параметры среды изменились после калибровки, профиль нужно пометить как требующий проверки, а не молча применять старые координаты.

### Блок D — управление профилем

- «Проверить обязательные поля»;
- «Сохранить профиль»;
- «Загрузить профиль»;
- «Сбросить профиль» с подтверждением;
- общий статус готовности.

Сохранение профиля не должно запускать очистку или рисование. Проверочные клики по игровым кнопкам выполняются только по явной команде пользователя.

## 4. Пользовательский сценарий задания координат

### Точка клика

1. Пользователь нажимает «Задать координаты» у конкретного элемента.
2. Программа показывает инструкцию: «Укажите центр кнопки [название]».
3. Пользователь наводит указатель и подтверждает точку способом, совместимым с используемой библиотекой ввода.
4. Программа сохраняет `x, y` только для выбранного элемента.
5. На экране отображаются координаты и статус «Задано».
6. Пользователь при желании запускает отдельную проверку.

**Важно:** способ подтверждения точки должен исключать конфликт между кликом по кнопке калибровки и кликом по игре. Реализация должна выбрать и протестировать безопасный механизм (например, горячую клавишу подтверждения после наведения), не предполагать его работоспособность без теста.

### Прямоугольная область

1. Пользователь нажимает кнопку задания именно нужной области.
2. Указывает первый угол, затем противоположный.
3. Программа нормализует координаты: `left=min(x1,x2)`, `top=min(y1,y2)`, `width=abs(x2-x1)`, `height=abs(y2-y1)`.
4. Отображает рамку и размеры области.
5. Пользователь подтверждает или повторяет выбор.

Области доски и полоски краски калибруются независимо. Нельзя автоматически вычислять область полоски из положения доски: интерфейс может отличаться между режимами.

Рекомендуемый файл: `testOnWin/brush_paint_calibration/calibration.json`.

Пример структуры (значения — иллюстративные, не реальные координаты):

    "windows_scale_percent": null,
    "board_logical_width": 460,

Координаты должны быть целыми экранными пикселями в единой системе отсчёта, принятой исполнителем. Если исполнитель использует другую систему координат, преобразование должно быть явным и протестированным. Не хранить реальные координаты как пример в коде по умолчанию.

## 6. Проверка калибровки

Проверка должна идти от безопасной к потенциально изменяющей состояние:

1. Проверить, что обязательные координаты заданы и находятся в пределах экрана.
2. Проверить прямоугольники: ширина и высота больше нуля, область внутри экрана.
3. Показать рамки областей без кликов по игре.
4. Проверить захват снимка доски и полоски краски: убедиться, что ROI включает нужный элемент и не захватывает посторонние элементы по возможности.
5. По явному нажатию пользователя проверить выбор кисти, затем убедиться по интерфейсу/снимку, что выбор сработал.
6. Проверить Clear только на тестовой пустой или заведомо ненужной доске: снимок до/после и сравнение показаний шкалы.
7. Сохранить результат проверки и дату.

Нажатие Clear уничтожает текущий рисунок, поэтому проверка не должна запускаться автоматически при сохранении профиля. Перед проверкой показывать предупреждение и запрашивать подтверждение.

## 7. Требования к тесту кисти и расхода

После калибровки тест должен использовать отдельные параметры, а не координаты, встроенные в код:

- выбрать кисть через соответствующую точку либо установить размер через откалиброванный слайдер;
- снять область доски до опыта;
- снять область полоски ресурса до опыта;
- выполнить траекторию внутри откалиброванной доски;
- снять те же области после опыта;
- записать размер кисти, параметры траектории, время, число точек исполнителя и наблюдаемые изменения;
- выполнить очистку только по явному шагу тестового сценария;
- проверить восстановление ресурса после очистки, поскольку в расширенном режиме возможна служебная базовая точка;
- сохранять сырые скриншоты и JSON/CSV-результаты.

Не считать `executor=completed` доказательством видимого или зарегистрированного игрой штриха. Раздельно фиксировать завершение ввода, изменение шкалы и видимый результат на доске.

## 8. Критерии готовности проекта к реализации

- [ ] У каждой кнопки/точки выбора кисти есть независимая кнопка задания координат.
- [ ] Область доски задаётся независимо от области полоски краски.
- [ ] Размер кисти 1 в расширенном режиме поддерживается отдельно от пресетов 7/14/20.
- [ ] Необязательные элементы не блокируют тест, если соответствующий режим не используется.
- [ ] Выбранные координаты и области визуально отображаются и проверяются.
- [ ] Профиль сохраняется и загружается без потери значений.
- [ ] Изменение разрешения/масштаба помечает профиль как требующий проверки.
- [ ] Сохранение профиля не кликает по игре и не стирает рисунок.
- [ ] Clear требует отдельного подтверждения при проверке.
- [ ] Есть тесты валидации JSON, координат, прямоугольников и статусов калибровки.
- [ ] Есть короткая инструкция для ручной калибровки на Windows.
- [ ] Фактический ввод/снимки проверены в браузере; без этой проверки не объявлять калибровку рабочей.

## 9. Порядок реализации

1. **Инвентаризация текущего кода:** найти существующие страницы/компоненты подготовки и исполнения, механизм сохранения профилей и ввод координат; переиспользовать подходящие компоненты, не дублировать систему профилей.
2. **Модель калибровки:** описать типизированные точки/области, статусы и версию схемы; добавить валидацию и тесты без управления мышью.
3. **UI точек:** сделать независимые строки Clear, кисти 7/14/20, кисти 1/слайдера и необязательных кнопок.
4. **UI областей:** реализовать независимый выбор доски, полоски краски и необязательного индикатора кисти.
5. **Сохранение/загрузка:** JSON-профиль, обратная совместимость при наличии старых настроек, понятные ошибки некорректного файла.
6. **Безопасная проверка:** визуализация рамок, захват ROI, подтверждаемые тестовые клики, защита от случайной очистки.
7. **Интеграция с тестом кистей:** заменить жёстко заданные координаты обращением к профилю; хранить профиль и отчёт каждого запуска.
8. **Валидация на Windows:** проверить разные разрешения/масштабы, повторную загрузку профиля и сценарий восстановления после ошибки.
9. **Документация и завершение:** инструкция, автоматические тесты, реальный ручной браузерный прогон, фиксация результатов в журнале проекта.

Этап считается выполненным только при наличии кода, тестов и проверяемого результата. Этот документ сам по себе является спецификацией, а не заявлением о реализованном интерфейсе.
