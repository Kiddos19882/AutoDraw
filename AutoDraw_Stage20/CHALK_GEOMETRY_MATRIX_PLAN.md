# План измерения расхода CHALK по геометрии и режиму ввода

**Статус:** G1 и G2 LIVE ACCEPTED; G3 исследовательский gate открыт, реализация block runner/UI/analyzer для G3 ещё требуется.  
**Дата:** 1 ноября 2026 г.  
**Предыдущая серия:** `chalk-20261101-023127-b85dbb`, 21/21 валидных прогонов.  
**Ветка:** `feature/image-geometry-optimization`.

## 1. Цель

Установить, какие параметры траектории и исполнения действительно меняют игровой расход CHALK, чтобы AutoDraw мог оценивать стоимость плана до рисования.

Завершённая матрица показала для шести длинных горизонтальных линий 722–728 CHALK при радиусах 1–30. Поэтому следующая серия не повторяет радиусный тест на той же геометрии, а изолирует другие факторы: длину, направление, короткие штрихи, число отдельных штрихов, повороты, замыкание, повторное покрытие, пересечения и скорость/sampling.

## 2. Непеременные правила

- Источник фактического расхода — только `post.pointCount - pre.pointCount`.
- `sampled_point_delta_total` — контроль согласованности с engine counter, а не замена ему.
- Длина пути, число executor move calls, число DRAW_SAMPLE, принятые игровые точки и визуальная площадь следа — разные показатели.
- Не делать вывод о CHALK по геометрической длине без проверки на игровых измерениях.
- На всех сериях фиксировать точный радиус, фактический `currentRadius`, transform/ROI, масштаб браузера, разрешение, состояние доски и параметры executor.
- Начальный радиус для геометрических серий: **10**. Он находится в середине диапазона и в radius matrix не показал отличающегося расхода. Перед каждым прогоном фактический радиус должен быть подтверждён Monitor.
- Не менять одновременно геометрию и executor sampling.
- Минимум три независимых повтора на каждую конфигурацию; порядок тестовых сценариев перемешивать фиксированным seed.
- Каждое измерение — чистая доска с baseline `pointCount`; не продолжать после непроверенного clear/reset.
- Safety stop: не запускать опыт, если прогнозируемый расход может превысить 80% квоты (4800 points); немедленно остановить серию при достижении этого порога или неполном исполнении.

## 3. Серия G1 — длина, направление и короткие штрихи

**Фиксировано:** радиус 10; штатный executor `point_step_px=2`, `point_delay_ms=10`; один сценарий за один experiment; три повтора.

Использовать уже существующие сценарии Brush Test:

| Сценарий | Проверяемые значения внутри сценария | Повторы |
|---|---|---:|
| `horizontal_lengths` | 10, 20, 50, 100, 200 px | 3 |
| `vertical_lengths` | 10, 20, 50, 100 px | 3 |
| `diagonal_lengths` | диагонали 20, 50, 100 по обеим координатам | 3 |
| `short_strokes` | 0, 1, 2, 3, 5, 8, 10 px | 3 |

Итого: **12 experiments**.

Анализировать:
- точный CHALK всего сценария;
- `pointDelta` по каждому strokeId, если lifecycle и события позволяют однозначную агрегацию;
- CHALK на один штрих и на 100 логических px только при подтверждённой полноте stroke-level событий;
- минимальную длину, при которой игра принимает точки;
- различие горизонтального, вертикального и диагонального направлений.

Нельзя делить общий CHALK сценария поровну между его штрихами: распределение должно быть получено из событий по strokeId и проверено суммой с точной общей дельтой.

## 4. Серия G2 — сегментация пути, повороты и перекрытие

**Фиксировано:** радиус 10; штатный executor; три повтора на сценарий.

| Сценарий | Что измеряет | Повторы |
|---|---|---:|
| `long_isolated_lines` | смешанная длина горизонтальных и вертикальных отдельных штрихов | 3 |
| `continuous_turns` | один штрих с прямыми углами, острыми поворотами и S-образной траекторией | 3 |
| `continuous_closed_contour` | замкнутые прямоугольный и треугольный маршруты | 3 |
| `repeated_coverage` | три прохода по одним координатам и отдельный контрольный проход | 3 |
| `parallel_spacing` | расстояния 4, 8, 16 и 24 px между параллельными линиями | 3 |
| `cross_section_intersections` | пересечения горизонтальных и вертикальных линий | 3 |

Итого: **18 experiments**.

Ключевые сравнения:
- одинаковая/сопоставимая суммарная длина при разном числе отдельных штрихов;
- непрерывный маршрут против разбиения на отдельные штрихи;
- повторный проход по уже нарисованным координатам против новой параллельной траектории;
- влияние поворотов, замыкания, пересечений и близкого spacing на число принятых игровых точек.

Для точного разделения стоимости по отдельным штрихам analyzer должен агрегировать `DRAW_SAMPLE.pointDelta` по `strokeId` и проверять, что сумма по всем strokeId равна общей exact CHALK. Если это условие не выполняется, per-stroke метрика маркируется incomplete и не используется для формулы.

## 5. Серия G3 — скорость и sampling

Проводится только после G1/G2. Геометрия — контрольный `paint_consumption_long_lines`, радиус 10, шесть линий. Меняется только пара параметров executor:

| `point_step_px` | `point_delay_ms` |
|---:|---:|
| 1 | 5, 10, 20 |
| 2 | 5, 10, 20 |
| 4 | 5, 10, 20 |

Три повтора на каждую комбинацию: **27 experiments**.

Порядок комбинаций рандомизировать заранее. Проверять 80%-ный safety stop. Сравнивать CHALK, move calls, число sampled/accepted points, длительность, FPS и event drops. Не считать увеличение числа move calls эквивалентным увеличению CHALK.

## 6. Требования к метаданным и анализатору

Текущий `chalk_radius_matrix` намеренно ограничен сценарием `paint_consumption_long_lines` и 6 штрихами. Для новых серий требуется отдельная универсальная схема `chalk_experiment_matrix`, не переинтерпретирующая старые radius manifests.

Каждый manifest новой серии должен содержать:
- `series_id`, `phase_id`, `scenario_id`, `repeat_index`, `matrix_order_index`;
- фиксированные параметры executor и фактический запрошенный/наблюдаемый радиус;
- ожидаемое число штрихов и конфигурацию геометрии;
- уникальные experiment ID и Game Monitor run ID;
- exact pre/post pointCount и capture diagnostics.

Analyzer должен:
1. проверить identity manifest/capture/summary и уникальность run ID;
2. проверить серию, фазу, сценарий, повтор и ожидаемые параметры;
3. проверить executor completion, точный радиус и число штрихов;
4. проверить exact positive CHALK, равенство `post-pre=consumed`, совпадение с `sampled_point_delta_total`;
5. исключить dropped events, monitor errors, reset, ambiguous correlation и неполные прогоны;
6. при доступной полной телеметрии построить stroke-level breakdown по strokeId и сверить его сумму с общей дельтой;
7. выдавать все первичные значения, среднее, медиану, диапазон и причины исключения.

## 8. Критерий завершения плана

План завершён, когда все конфигурации G1–G3 имеют по три валидных независимых повтора либо документированную причину исключения/остановки; per-stroke aggregation подтверждена или явно помечена недоступной; создана сводная модель, которая отделяет фактический CHALK от длины, move calls, sampling и качества покрытия. Production planner не должен считать модель валидированной, пока её прогноз не проверен на независимых контрольных рисунках.
