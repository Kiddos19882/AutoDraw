# AutoDraw: гибридная оптимизация преобразования в палитру

## Цель

Палитра браузерного холста уже известна и должна оставаться точной. Поэтому задача отличается от создания произвольной палитры для GIF/PNG: важно выбрать правильный доступный цвет для каждого участка и одновременно снизить число коротких scanline-штрихов, которые игра может регистрировать ненадёжно.

## Рассмотренные подходы

1. **Ближайший цвет по RGB** — очень быстрый, но геометрическое расстояние в RGB неравномерно соответствует человеческому восприятию.
2. **CIELAB + CIEDE2000** — текущая основа AutoDraw: выбор наиболее похожего цвета из фактической палитры в перцептивном цветовом пространстве. Она сохраняет точные цвета палитры и позволяет задавать ограничение допустимого изменения цвета.
3. **Median Cut, Octree, Wu, K-means/Lloyd** — применяются для построения новой сокращённой палитры из изображения. Они полезны, когда изображение может получить любые новые цвета, но не должны заменять обнаруженные цвета браузерной палитры: итоговые RGB должны совпадать с реально выбираемыми цветами игры.
4. **Dithering / error diffusion (например, Floyd–Steinberg)** — помогает визуально имитировать промежуточные оттенки при малом количестве цветов, но достигает этого чередованием соседних цветов. Для рисования линиями такое чередование может увеличить число коротких сегментов, поэтому в AutoDraw дизеринг намеренно выключен.
5. **Объединение редких цветов** — существующий шаг: редкий цвет заменяется похожим частым цветом с ограничением CIEDE2000. Он хорошо удаляет цветовые единичные выбросы, но глобальная частота не обнаруживает все короткие фрагменты, если этот же цвет часто используется в других местах.
6. **Новая пространственная оптимизация коротких горизонтальных сегментов** — дополнение к предыдущему шагу. Для сегментов короче порога рассматриваются соседние цвета строки. Цвет можно заменить, только если его ΔE00 не превышает порог. Если с обеих сторон один цвет — это сильное локальное основание для замены. Если соседи различны или сегмент расположен у края изображения, целевой цвет должен также быть существенно более частым во всём изображении. Несколько проходов позволяют схлопывать каскады коротких похожих сегментов.

## Цепочка алгоритма

1. Сохранить геометрию исходного изображения и прозрачность.
2. Преобразовать каждый видимый пиксель в ближайший реальный цвет палитры с помощью CIEDE2000.
3. Применить существующее осторожное объединение глобально редких цветов.
4. Применить локальное объединение слишком коротких горизонтальных сегментов с ограничением ΔE00 и защитой контрастных деталей.
5. Если выбран режим удаления белого/фона, оставить управление прозрачностью в его отдельном шаге.
6. Отобразить в отчёте изменение количества коротких сегментов, число переназначенных пикселей, оценку числа scanline-штрихов до/после и цветовое отличие.

## Стартовые параметры

- Минимальная длина сегмента: 3 px — рассматриваются только отрезки длиной 1–2 px.
- Максимальное отличие: ΔE00 ≤ 8.
- Если нет одинакового цвета по обеим сторонам: цвет-кандидат должен быть минимум в 1,25 раза более частым.
- Максимум проходов: 2.

Эти значения являются консервативными стартовыми настройками, а не гарантией игрового распознавания. Для игры, которая теряет более длинные линии, порог можно увеличить до 5–10 px, однако это повышает риск потери мелких деталей. Рекомендуется сначала сравнить предпросмотр и отчёт на копии изображения.

## Ограничения

- Метрика штрихов считает переходы между цветами по строкам; это оценка для scanline-планировщика, а не точный прогноз расхода ресурса игры.
- Оптимизация меняет изображение и потому может удалять тонкие детали. Высококонтрастные фрагменты за пределом ΔE00 сохраняются.
- Реальное качество и регистрация штрихов подтверждаются только проверкой на целевом браузерном холсте Windows.
