# AutoDraw 1.8.3

Единое приложение для подготовки изображений, работы с игровой палитрой, построения цветных планов и исполнения рисунка на холсте.

> **ВАЖНО: границы локального доступа и обязательная автоматизация тестов**
>
> Доступ к запущенной локальной программе AutoDraw, браузерной игровой сессии и реальной доске рисования в игре есть только у пользователя. Только пользователь может запускать и непосредственно выполнять live-тесты в этой среде. Локальная рабочая копия Git на ПК пользователя, включая фактический вывод `git status`, также доступна только пользователю.
>
> ИИ может работать с доступным удалённым содержимым GitHub, исходниками, документацией, тестами и CI, но это **не является** доступом к локальному ПК, локальному `git status`, запущенной программе или игровой доске. Нельзя заявлять о локальной проверке или live-тесте без полученного от пользователя результата/артефактов.
>
> Все тесты взаимодействия AutoDraw с реальной игровой доской должны быть максимально автоматизированы. Следует сначала повторно использовать существующие harness, Game Monitor, Bridge, executor, сценарии и сборщики evidence; недостающие условия и средства автоматизации необходимо создавать в рамках отдельно разрешённого объёма. Автоматизировать подготовку и запуск сценариев, фиксацию параметров и телеметрии, измерение точного расхода по `pointCount`, сохранение исходных артефактов, анализ критериев и формирование отчётов. Ручные действия пользователя сводить к необходимому минимуму; действия, требующие локального доступа или физического/интерактивного участия пользователя, явно обозначать. Автоматизация не предоставляет ИИ удалённый доступ и не отменяет необходимость разрешения на live-эксперимент.


## Генерация кандидатного корпуса для CHALK validation

Для пакетного создания .autodraw проектов и color scanline планов из исходных изображений используй CLI:

```powershell
python source/preparation/generate_validation_corpus.py --input "C:\path\to\images" --palette "data\palettes\profiles\palette-profile.json"
```

Результаты сохраняются в data/projects/generated_validation_corpus/, data/results/color_scanline_plans/generated_validation_corpus/ и manifest data/results/generated_validation_corpus_manifest.json. Для monochrome-only режима добавь --skip-color-plans. Требования к происхождению данных и статистические ограничения описаны в [документе генератора](docs/VALIDATION_CORPUS_GENERATOR_2026-11-07.md). Сгенерированные записи являются кандидатами, а не автоматически одобренной calibration/holdout выборкой.

## Windows: тестирование и сборка

Запусти `build_windows.bat`. Скрипт устанавливает зависимости, выполняет предусмотренные проверки, собирает portable-приложение и запускает smoke-test. Сборка подтверждает запуск приложения, но не заменяет ручную проверку UI и рисования в браузере.

Вкладка 8 «FILL-001» предназначена для контролируемых геометрических экспериментов с расходом CHALK; матрица из 45 задач запускается только по одной задаче и остаётся заблокированной до Windows live preflight. Вкладка 9 «Калибровка теста» хранит независимые экранные координаты кнопок кисти/очистки и области доски/шкалы краски в `data/profiles/brush_paint_calibration.json`. Перед использованием проверь координаты после изменения разрешения или масштаба.

`app_features.json` — источник списка функций, включаемого в `build_info.json`. Не включай профиль палитры с абсолютными координатами другого экрана в начальную portable-сборку. При обновлении необходимо сохранять пользовательские данные.
