## 5. Предварительные закономерности

### 5.1. Задержка точки влияет на CHALK

При фиксированном шаге результаты 5 и 10 ms почти совпадают:
- step=1: 1355 против 1354.5;
- step=2: 713.67 против 715.5;
- step=4: 362.33 против 363.5 (для delay=10 один из двух результатов partial).

При delay=20 расход существенно выше:
- step=1: 2071.67 против примерно 1354.7 при delay 5/10, около +53%;
- step=2: 1381 против примерно 714.6, около +93%;
- step=4: 713.33 против примерно 362.9, около +97%.

Это указывает, что расход зависит от времени прохождения пути/частоты игровых выборок, а не только от количества вызовов перемещения. Возможное объяснение — игровой sampling на кадрах: при 5/10 ms исполнитель может отправлять координаты быстрее, чем игра успевает их обработать, тогда как 20 ms меняет временной профиль. Это гипотеза, а не доказанная внутренняя формула движка.

### 5.2. Шаг перемещения также влияет на CHALK

При одинаковой задержке меньший `point_step_px` даёт больше принятых игровых точек. Для delay=5/10 средний расход примерно:
- step=1: 1354–1355;
- step=2: 714–716;
- step=4: 362–364.

Это согласуется с тем, что более плотная последовательность координат создаёт больше возможностей для игровых выборок. Но зависимость не является простой линейной функцией одного лишь числа `move_calls`.

### 5.3. Важна комбинация параметров

При delay=20 соотношение расходов между шагами отличается от delay=5/10. Значит, параметры взаимодействуют: модель вида «расход = константа × число перемещений» не подтверждается этими данными.

## 6. Что пока нельзя заключать

- Радиус кисти во всей серии фиксирован на 10. G3 не измеряет влияние размера кисти; для этого нужна отдельная серия с разными радиусами при контролируемых остальных параметрах.
- Геометрия только одна: шесть длинных горизонтальных линий. Нельзя переносить коэффициенты напрямую на короткие штрихи, диагонали, повороты, перекрытия или заполнение областей.
- Все trajectory summaries имеют `incomplete_until_verified`; точную принятую длину пути по текущему Monitor event stream восстановить нельзя.
- Частичный capture для 4/10/r2 нельзя приравнивать к полному повтору.
- Средние по неполным ячейкам являются предварительными и не должны использоваться как окончательные коэффициенты планировщика AutoDraw.
- По этой серии нельзя вывести универсальную формулу CHALK для всех размеров кисти, цветов и типов рисунка.

## 9. Проверка возможности продолжения закрытого блока

Проверен код на том же commit, что и исходные результаты:

- `claim_next_chalk_block_task()` отказывает для block status `stopped` и не выдаёт следующую pending-задачу;
- UI recovery scan рассматривает `ready/running/paused/failed`, но не `stopped`;
- `resolve_interrupted_chalk_block_task()` принимает только task status `interrupted`; failed-задача не может быть автоматически переведена в pending;
- UI recovery допускает retry ровно одной interrupted-задачи после ручного подтверждения проверки доски; для failed-задачи интерфейс прямо запрещает автоматический retry;
- `build_chalk_test_block_plan(phase_id="G3")` всегда строит полные 27 ячеек (9 конфигураций × 3 повтора), а не частичную шестизадачную continuation-матрицу.

Следовательно, штатный UI/code path не умеет продолжить именно этот stopped block или создать штатную G3 continuation-матрицу только из шести задач. Не менять вручную journal и не переоткрывать stopped block. Без изменения механизма продолжения корректный штатный путь — новая полная G3 серия 27/27. Альтернатива — отдельная разработка и тестирование формального continuation/aggregation механизма, который явно связывает исходный и дочерний block IDs и не позволяет задвоить уже принятые captures.
