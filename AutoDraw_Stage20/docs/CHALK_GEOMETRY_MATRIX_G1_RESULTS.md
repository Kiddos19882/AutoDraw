## 2. Точные значения CHALK

Источник расхода — только `post.pointCount - pre.pointCount`. Во всех 12 отчётах baseline равен 1, post counter и точная дельта согласованы.

| Сценарий | Три точных расхода | Среднее | Диапазон |
|---|---:|---:|---:|
| Горизонтальные линии | 122, 124, 120 | 122,00 | 120–124 |
| Вертикальные линии | 60, 61, 61 | 60,67 | 60–61 |
| Диагональные линии | 75, 76, 76 | 75,67 | 75–76 |
| Короткие штрихи | 19, 18, 17 | 18,00 | 17–19 |

Средние значения являются описательной статистикой трёх фактических запусков, но до устранения повторяющегося `repeat_index` не являются результатом принятой анализатором complete repeat group.

## 3. Проверка Game Monitor и per-stroke breakdown

Проверены все 12 `monitor_report.json`:

- `chalk.status=exact`;
- наблюдаемый радиус — только 10;
- `stroke_count` совпадает с ожидаемым количеством штрихов;
- dropped events = 0;
- monitor errors = 0;
- сумма `DRAW_SAMPLE.pointDelta` по уникальным `strokeId` совпадает с точной общей CHALK;
- количество уникальных `strokeId` совпадает с ожидаемым количеством штрихов.

### Средний расход по позициям штрихов

Значения приведены в порядке штрихов соответствующего плана. Это средние по трём физическим запускам, рассчитанные из подтверждённых per-stroke `pointDelta`.

| Сценарий | Расход по отдельным штрихам (среднее) |
|---|---|
| Горизонтальные 10/20/50/100/200 px | 5,00 / 7,67 / 16,33 / 31,67 / 61,33 |
| Вертикальные 10/20/50/100 px | 4,67 / 8,00 / 16,67 / 31,33 |
| Диагонали 20/50/100 px по обеим координатам | 9,67 / 22,33 / 43,67 |
| Короткие 0/1/2/3/5/8/10 px | 1,00 / 1,00 / 2,67 / 2,00 / 2,33 / 4,33 / 4,67 |

Полные первичные per-stroke суммы по повторам:

- Horizontal: [5, 8, 16, 32, 61], [5, 8, 17, 32, 62], [5, 7, 16, 31, 61].
- Vertical: [5, 8, 16, 31], [5, 8, 17, 31], [4, 8, 17, 32].
- Diagonal: [9, 22, 44], [10, 22, 44], [10, 23, 43].
- Short: [1, 1, 3, 2, 2, 5, 5], [1, 1, 2, 2, 3, 4, 5], [1, 1, 3, 2, 2, 4, 4].

Это подтверждает полноту распределения CHALK между штрихами по event stream. При этом `trajectory.status=incomplete_until_verified` остаётся корректной отметкой: из-за coalescing Monitor не гарантирует восстановление всех промежуточных координат и точной фактической длины пути. Per-stroke CHALK и точная геометрическая длина — разные метрики.

## 4. Существенная проблема metadata

Во всех 12 `chalk_experiment_matrix` записано `repeat_index=1`. Следовательно, в каждой группе сценария три различных физических запуска занимают одну и ту же логическую ячейку повторения.

Дополнительно поле `matrix_order_index`, указанное в требованиях плана к manifest, в проверенных matrix metadata отсутствует.

Последствия:
- три физических запуска каждого сценария присутствуют и имеют уникальные experiment/run ID;
- все 12 индивидуальных измерений проходят проверки точного CHALK, радиуса, количества штрихов и per-stroke суммы;
- строгая проверка уникальности repeat cell не может принять группы как повторы 1/2/3;
- нельзя объявлять G1 полностью закрытой и открывать G2 на основании текущей маркировки.

**Первичные manifests и monitor reports не исправлялись.** Не следует молча переписывать `repeat_index` задним числом. Требуется отдельное согласованное решение по восстановлению индексов либо повторный сбор недостающих корректно маркированных повторов.

## 5. Предварительная интерпретация

1. Расход не пропорционален только суммарной длине пути. Горизонтальный сценарий (380 логических px) расходует около 122 CHALK, вертикальный (180 логических px) — около 60,67 CHALK; диагональный (около 240,42 логических px) — около 75,67 CHALK.
2. В рамках этих геометрий направление и алгоритм приёма/дискретизации точек влияют на результат. Эти данные не изолируют все причины различия и не позволяют вывести универсальный коэффициент «CHALK на пиксель».
3. Короткие штрихи имеют фиксированную стоимость старта: нулевой и 1 px штрихи дали по одной принятой точке в каждом из трёх запусков. Для длины 2 px получено 2–3 точки; дальнейший рост расхода не строго линейный на этом малом диапазоне.
4. Per-stroke CHALK можно использовать как точную наблюдаемую метрику в этих запусках; геометрическую длину пути по текущей телеметрии нельзя считать полностью восстановленной.
5. Результаты относятся к радиусу 10 и зафиксированному executor config. Они не доказывают поведение других радиусов, sampling settings, поворотов, перекрытий или повторного покрытия.
