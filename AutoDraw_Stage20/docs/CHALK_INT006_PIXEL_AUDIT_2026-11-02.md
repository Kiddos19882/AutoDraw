## 2. Метод анализа

Для каждого опыта сравнивались `before_clear-board.png` и `after_draw-board.png`. Маска краски получалась по потемнению относительно blank reference: luminance delta >=22 и observed luminance <=205. Плановая геометрия бралась из `experiment.json → chalk_experiment_matrix.planned_strokes`, а не восстанавливалась из coalesced Monitor events.

Logical DrawingPlan переводился в пиксели изображения с учётом размеров board capture и Monitor logicalWidth/logicalHeight. Штрихи сегментировались в коридорах шириной `max(7 screen px, brush radius × mean image scale × 0.65 + 1 screen px)`. Пиксели на равном расстоянии от нескольких коридоров маркировались ambiguous и не включались в индивидуальные метрики. Для cursor exclusion использовалась яркая компонента около последней точки траектории с расширением 13×13.

Порог достаточности path metrics: не менее 80% плановых samples должны оставаться оцениваемыми после исключения cursor/ambiguous областей. Это порог пригодности измерения, не критерий качества рисунка.

**Ограничения метода:** дифференциальная маска чувствительна к luminance threshold и anti-aliasing; тёмный контур курсора может остаться, если тело курсора не распознано. Width — измеренная ширина пиксельной маски при данном threshold, а не доказанная физическая ширина кисти. Автоматический quality pass/fail не задавался.

## 5. Важные частные результаты

### V2 — короткие движения

Все 9 опытов имеют одинаковую проблемную строку `length_10`: planned length около 9.986 logical px, evaluable path fraction=0.381, width CV около 0.71–0.79 и две mask components. Она не проходит порог достаточности 0.8. Остальные длины 1/2/3/5/8 px проходят порог.

Вывод: при radius=10 движения длиной около 10 logical px нельзя достоверно оценивать как непрерывную линию текущим pixel-level методом. Круглые отпечатки и короткая траектория сопоставимы с радиусом/шириной следа. Нужен отдельный короткий тест с геометрией, пригодной для оценки центральной линии, и отдельная интерпретация point/spot strokes.

### V4 — замыкание контуров

Для rectangle и triangle closure seam покрыт во всех повторах. Для irregular_polygon closure seam metric отсутствует (NaN), поэтому нельзя заявлять полное численное подтверждение замыкания всех трёх фигур. Coverage по оцениваемой части всех трёх контуров равна 1.0. Нужен просмотр диагностических overlay для участка, ранее перекрытого курсором, и проверка endpoint/closure логики на irregular polygon.

### V5 — параллельные линии

Получено 144 сравнения пар. В 9/144 есть пересечение candidate masks, и все эти 9 случаев классифицированы как касание/слияние assigned ink masks. Они соответствуют повторяемой близкой паре `parallel_close_a / parallel_close_b` со spacing около 8.01 logical px: candidate overlap — около 1,877–1,885 screen pixels на опыт, минимальная дистанция ink masks около 2.37 logical px. Остальные пары не отмечены как слияние по принятому порогу.

Это подтверждает, что spacing около 8 logical px в текущем тесте сливает следы. Это не устанавливает универсальный безопасный spacing: для него нужны дополнительные интервалы между 8 и 24 logical px и контрольная визуальная проверка. Параллельные метрики зависят от маски и порога касания.

### V1/V3 — геометрическая изоляция

В масках остаются несколько connected components для части штрихов: V1 — 18/54, V3 — 27/27. Это согласуется с известными пересечениями/соприкосновениями тестовых геометрий и ограничивает интерпретацию отдельных per-stroke masks. Нулевой gap по оцениваемой траектории не отменяет необходимость разнести геометрии и повторить тесты.

## 6. Что пока нельзя заключить

1. Нельзя объявлять P1/P2 production default только по pixel metrics: независимые targeted reruns V1/V3 и коротких штрихов ещё нужны.
2. Нельзя использовать measured width около 8.5 logical px как фактический диаметр кисти: это threshold-dependent differential mask.
3. Нельзя закрывать визуальный gate только по coverage=1/gap=0: есть ambiguous/cursor exclusions, компоненты масок и ограничения V2/V4.
4. Нельзя определить точный минимальный spacing параллельных штрихов по одной паре 8/24 px.
5. Pixel audit не измеряет расход CHALK. Для расхода остаются authoritative exact CHALK/pointCount deltas из Monitor; pixel metrics описывают геометрию следа.

## 8. Коррекция post-draw cursor occlusion для V4

Проблема была в процедуре захвата: после завершения рисования курсор оставался на конечной точке, а screenshot выполнялся без предварительного перемещения. В экспериментальном UI добавлен cursor-free capture sequence:

1. Получить первичный screenshot для проверки фактического разрешения экрана.
2. Рассчитать ближайшую допустимую точку с отступом 24 screen px за пределами calibrated board ROI.
3. Выполнить `pyautogui.mouseUp()` для гарантированного освобождения кнопки.
4. Переместить курсор в рассчитанную точку без клика (`pyautogui.moveTo(..., duration=0)`).
5. Выдержать 150 ms и сделать новый screenshot; board ROI и paint meter crop формируются только из второго снимка.
6. Записать в `experiment_phases.after_draw.cursor_exclusion` метод, точку и margin.

Если безопасная точка вне экрана недоступна или координаты некорректны, post-draw capture завершится ошибкой вместо сохранения потенциально закрытого курсором кадра. Это fail-closed поведение. Добавлены тесты геометрии выбора точки и порядка действий. Кодовые коммиты: `a680f51`, `d299259`, `723a410`. CI для нового HEAD и реальный V4 capture ещё не подтверждены; старые captures не изменялись.
