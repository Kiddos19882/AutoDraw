# INT-006 — первичный скрининг PNG V1–V5

**Дата:** 2026-11-02  
**Ветка:** `feature/image-geometry-optimization`  
**Основа:** первичные captures из data commit `64795362aa1bf4d0a3587e119b8c959242be6181`; просмотрены оригинальные `after_draw-board.png`, полученные из GitHub.  
**Статус:** предварительный визуальный скрининг выполнен; количественный pixel-level аудит остаётся открытым.

## 1. Объём просмотра

Просмотрены репрезентативные изображения по каждому из пяти сценариев V1–V5 и каждому sampling profile:
- P0: `point_step_px=2`, `point_delay_ms=10`;
- P1: `point_step_px=4`, `point_delay_ms=5`;
- P2: `point_step_px=4`, `point_delay_ms=10`.

Итого просмотрено 15 оригинальных board ROI: по одному representative capture на профиль и фазу. Это не полный просмотр всех 45 PNG и не автоматическая сегментация.

## 2. Наблюдения по геометрии

| Фаза | Наблюдение по PNG | Ограничение |
|---|---|---|
| V1 — диагонали | Все видимые диагонали непрерывны во всех трёх профилях. Очевидного ухудшения P1/P2 относительно P0 не видно. | `slope_050` пересекается с `negative_shallow`; набор не полностью изолирован. |

| V3 — повороты | Ломаные визуально непрерывны во всех профилях; разницы в непрерывности step=4 против step=2 не обнаружено. | `right_angle` пересекается с `acute_zigzag`; углы округлены шириной следа. |

## 3. Сравнение sampling profiles

На просмотренных representative captures:
- P1 и P2 не демонстрируют очевидных пропусков штриха или разрывов, отсутствующих у P0.
- Между P1 (delay=5) и P2 (delay=10) визуальная разница не обнаружена.
- В V1/V3 небольшие неровности контура штриха видны при всех профилях; визуального основания объявлять step=4 хуже или лучше по точности centerline пока нет.
- В V2 одинаковый вид точек не означает одинаковую линейную непрерывность: тестовая геометрия и радиус не позволяют сделать такой вывод.

Это только предварительная оценка по 15 снимкам. Она не заменяет полный аудит повторов и заранее заданные численные критерии.

## 4. Количественные метрики — НЕ рассчитаны

Для всех 45 captures ещё требуется вычислить:
1. **Continuity / max gap:** крупнейший разрыв вдоль ожидаемой траектории после удаления фона и сегментации следа кисти.
2. **Centerline deviation:** расстояние между извлечённой центральной линией следа и заданной траекторией DrawingPlan.
3. **Coverage width:** ширина следа поперёк локального направления траектории, медиана и квантили.
4. **Width variation:** разброс ширины вдоль каждого штриха.
5. **Contour closure:** расстояние между концами и наличие разрыва в местах замыкания контура.
6. **Parallel separation:** расстояние между границами следов и факт их слияния для каждой пары.

Перед массовым расчётом необходимо зафиксировать параметры сегментации на blank-board reference и вручную проверить false-positive/false-negative на representative PNG. Нельзя автоматически считать каждый тёмный пиксель краской: курсор, интерфейсные элементы и артефакты ROI должны исключаться.

## 5. Что можно заключить сейчас

- Предварительный просмотр не выявил явной деградации непрерывности при step=4 в диагоналях, ломаных, контурах и узлах.
- V1 и V3 требуют исправленных изолированных геометрий для чистого анализа диагоналей и поворотов.
- V2 измеряет цену короткого движения, но не качество короткой линии.
- V4 closure нельзя окончательно подтвердить там, где соединение закрывает курсор.
- V5 подтверждает визуальное слияние пары при spacing=8 logical px, но точный минимальный интервал разделения не установлен.
- Нельзя закрывать pixel-level quality gate и нельзя менять production defaults/estimator по этому скринингу.

## 6. Следующие действия

1. Выполнить количественную сегментацию всех 45 PNG относительно blank-board reference; сохранить per-stroke metrics и визуальные diagnostic overlays.

**Решение:** этап первичного визуального скрининга выполнен; количественный pixel-level аудит остаётся следующим активным подэтапом INT-006. Production code, executor defaults и estimator не изменялись.


## 7. Инвентаризация полного набора и ограничение количественного анализа

По Git tree исходного data commit `64795362aa1bf4d0a3587e119b8c959242be6181` подтверждено наличие полного набора:
- 45 experiment directories;
- 45 `experiment.json`;
- 45 `monitor_report.json`;
- 45 `before_clear-board.png`;
- 45 `after_draw-board.png`;
- 45 `after_draw-screen.png`;
- всего 270 PNG в шести capture-категориях на каждый experiment.

Размеры всех `after_draw-board.png` суммарно — 594,826 bytes; `before_clear-board.png` — 107,685 bytes. Blank/reference board capture, таким образом, сохранён для каждого run и может использоваться для differential segmentation.

**Почему численные метрики пока не рассчитаны:** GitHub connector предоставляет binary PNG в base64/preview форме, но текущая рабочая среда не передаёт эти бинарные данные в локальный Python/OpenCV runtime как файлы. Прямая загрузка raw GitHub из контейнера также недоступна из-за отсутствия DNS/network. Просмотр изображения через preview не даёт достоверных pixel arrays. Поэтому вычислять или публиковать max gap, centerline deviation, width и closure по этим preview было бы недостоверно.

Это ограничение среды анализа, а не отсутствие исходных данных: все 45 пар blank/after-draw PNG присутствуют в репозитории.

## 8. Условия для продолжения количественного аудита

Количественный этап следует запускать в среде, где checkout commit `6479536` доступен локально:
1. Установить зависимости из `source/preparation/requirements.txt` (Pillow, NumPy, OpenCV).
2. Для каждой experiment directory загрузить `before_clear-board.png`, `after_draw-board.png` и planned geometry из `experiment.json`.
3. Получить differential ink mask, исключить постоянный фон и ограничить анализ коридорами planned strokes.
4. Отдельно маркировать участки, перекрытые курсором, интерфейсом, пересечениями или соседними штрихами; не выдавать ambiguous зоны за валидные метрики.
5. Сначала вручную проверить mask/overlay на одном run каждой фазы и каждого профиля, затем выполнять пакетный расчёт всех 45 captures.
6. Сохранять CSV/JSON per-stroke metrics и диагностические overlay в отдельном output directory; исходные captures не изменять.

**Важно:** не применять автоматический порог к абсолютному цвету без differential reference. Курсор и пересечения должны иметь отдельный ambiguous mask. До появления численных результатов pixel-level gate остаётся OPEN.
