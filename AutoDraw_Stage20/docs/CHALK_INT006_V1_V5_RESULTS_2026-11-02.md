## 1. Итог исполнения

В коммите сохранены пять block journals V1–V5, каждый рассчитан на 9 задач: три sampling profiles × три повтора.

| Фаза | Сценарий | Штрихов в задаче | Задач completed |
|---|---|---:|---:|
| V1 | Диагонали разных наклонов | 6 | 9/9 |
| V2 | Короткие штрихи 1, 2, 3, 5, 8, 10 logical px | 6 | 9/9 |
| V3 | Ломаные с поворотами | 3 | 9/9 |
| V4 | Замкнутые контуры | 3 | 9/9 |
| V5 | X/T/крестовые узлы и параллельные линии | 10 | 9/9 |
| **Итого** | **5 фаз** | **252 запланированных штриха** | **45/45** |

Каждый capture принят по основным telemetry gates:

- executor завершён; фактическое число strokes совпало с ожидаемым;
- `monitor_capture.status=saved`;
- `chalk.status=exact`, 45/45;
- `point_delta_matches_chalk=true`, 45/45;
- радиус кисти единственный и равен 10;
- `dropped_events=0`, `monitor_buffer_dropped_events_delta=0`;
- `monitor_error_count_delta=0`, `bridge_send_failures_delta=0`, `collector_sequence_gap_count=0`;
- все block journals имеют `status=completed`;
- до запуска следующей задачи доска восстанавливалась в пределах заданного pixel tolerance.

В monitor reports `accepted_points` сгруппированы по `stroke_id`: для всех 45 задач число групп совпадает с числом запланированных strokes, `non_consuming_stroke_candidate_count=0`, сумма per-stroke `point_delta` совпадает с exact CHALK. Это позволяет анализировать стоимость каждого штриха отдельно. Координатная траектория при этом может быть неполной из-за coalescing; per-stroke расход точен, но восстановление всех промежуточных координат не подтверждено.

## 3. Exact CHALK по геометрическим сценариям

Значения в ячейках — три отдельных повтора; среднее рассчитано по ним. Сравнение проводится только внутри одной геометрии.

| Фаза | P0: step2/delay10 | P1: step4/delay5 | P2: step4/delay10 | Снижение P1 / P2 против P0 |
|---|---:|---:|---:|---:|
| V1 диагонали | 243, 243, 245 (**243.67**) | 127, 127, 126 (**126.67**) | 127, 128, 127 (**127.33**) | **48.0% / 47.7%** |
| V2 короткие | 21, 18, 21 (**20.00**) | 15, 16, 14 (**15.00**) | 15, 15, 16 (**15.33**) | **25.0% / 23.3%** |
| V3 повороты | 381, 382, 379 (**380.67**) | 194, 194, 193 (**193.67**) | 193, 194, 194 (**193.67**) | **49.1% / 49.1%** |
| V4 контуры | 450, 448, 448 (**448.67**) | 229, 229, 229 (**229.00**) | 231, 229, 229 (**229.67**) | **49.0% / 48.8%** |
| V5 пересечения/параллели | 441, 442, 441 (**441.33**) | 229, 230, 229 (**229.33**) | 228, 231, 228 (**229.00**) | **48.0% / 48.1%** |

### Выводы по расходу

1. На V1, V3, V4 и V5 step=4 снижает суммарный расход примерно на 48–49% относительно step=2.
2. На V2 экономия ниже — примерно 23–25%. Для очень коротких strokes заметна стартовая стоимость: каждый отдельный штрих потребляет минимум около двух игровых точек в этой серии.
3. P1 и P2 практически равны по расходу во всех пяти сценариях. Изменение delay с 5 до 10 ms не даёт измеримого преимущества по CHALK в этой матрице.
4. Результаты согласуются с G3: для длинных траекторий step=4 даёт примерно половину расхода step=2. Переносить один общий коэффициент на короткие штрихи нельзя.

## 4. Per-stroke анализ коротких штрихов V2

Шесть strokes имеют длины 1, 2, 3, 5, 8 и 10 logical px. Ниже — средний exact расход на один stroke по трём повторам.

| Длина, logical px | P0 step2/delay10 | P1 step4/delay5 | P2 step4/delay10 |
|---:|---:|---:|---:|
| 1 | 2.00 | 2.00 | 2.00 |
| 2 | 2.67 | 2.00 | 2.00 |
| 3 | 2.67 | 2.00 | 2.00 |
| 5 | 3.67 | 2.33 | 2.67 |
| 8 | 4.00 | 3.00 | 3.00 |
| 10 | 5.00 | 3.67 | 3.67 |

Наблюдение: для сегментов 1–3 px доминирует минимальная стоимость старта, поэтому увеличение step почти не снижает расход. Для 8–10 px разница уже заметнее. Это кандидат на отдельный lookup для коротких сегментов, а не основание экстраполировать линейную модель длинных штрихов.

При radius=10 короткие движения визуально выглядят как отдельные точки/круглые отпечатки, а не как полноценные линейные отрезки. V2 полезен для измерения стоимости короткого движения, но не является проверкой непрерывности тонкой линии.

## 5. Независимая проверка исходной модели на контрольном P0

Исходная модель G1 для отдельного штриха при radius=10, step=2, delay=10:

`CHALK_stroke ≈ 1.765 + 0.2988 × L`

где `L` — длина штриха в logical board pixels.

Для первичной holdout-проверки использованы per-stroke данные P0 из V1, V3, V4 и V5: 66 strokes, длины больше 10 px. Короткие strokes V2 исключены, поскольку для них модель заранее предусматривала отдельный lookup. Коэффициенты исходной G1-модели не переобучались на этой выборке.

| Метрика | Результат |
|---|---:|
| Число независимых per-stroke наблюдений | 66 |
| MAE | 1.09 CHALK |
| RMSE | 1.33 CHALK |
| Bias (actual − predicted) | −1.04 CHALK |
| MAPE | 1.71% |
| Максимальная абсолютная ошибка | 4.12 CHALK |

Отрицательный bias означает, что исходная модель в среднем немного завышает расход — консервативное направление ошибки для планирования квоты. Это сильный предварительный результат на новых формах, но не полная validation production estimator: выборка ограничена пятью тестовыми сценариями, V1/V3 имеют пересечения траекторий, а независимые полноценные рисунки и отдельная validation коротких strokes ещё нужны.

## 6. Исследовательская оценка коэффициента step=4

По 66 per-stroke наблюдениям на V1/V3/V4/V5 получены отдельные линейные аппроксимации:

| Профиль | Исследовательская аппроксимация | MAE fit | RMSE fit | MAPE fit |
|---|---|---:|---:|---:|
| P1 step4/delay5 | `C ≈ 1.475 + 0.148865 × L` | 0.315 | 0.400 | 1.15% |
| P2 step4/delay10 | `C ≈ 1.440 + 0.149151 × L` | 0.378 | 0.472 | 1.44% |

Это fit на тех же наблюдениях, а не независимая проверка step=4 модели. Полученный наклон около 0.149 CHALK/logical px близок к G3 коэффициентам step=4 (около 0.152 CHALK/logical px). Коэффициенты оставить исследовательскими до отдельной holdout-проверки step=4.

## 7. Визуальная проверка сохранённых PNG

Выполнено обзорное сравнение репрезентативных captures P0 и P1 по всем пяти фазам. Это ручной визуальный осмотр PNG на обзорном масштабе, не pixel-level segmentation.

- **V1:** диагональные линии выглядят непрерывными; обнаружено непреднамеренное пересечение `slope_050` и `negative_shallow` в точке (340, 80). Поэтому набор не является полностью изолированным тестом диагоналей.
- **V2:** все шесть коротких движений оставили видимые круглые отметки; из-за radius=10 они не выглядят как различимые линейные отрезки.
- **V3:** ломаные визуально непрерывны, но `right_angle` пересекается с `acute_zigzag` примерно в (233.33, 100). Это смешивает проверку поворотов с пересечением.
- **V4:** прямоугольник, треугольник и неправильный контур визуально замкнуты; у углов ожидаемо видны округления следом кисти. Часть одного контура перекрыта курсором на обзорном снимке.
- **V5:** X/T/крестовые узлы видимы. Параллельные линии с расстоянием 8 logical px сливаются в одну полосу; пара с расстоянием 24 logical px остаётся визуально раздельной. Это качественное наблюдение по screenshot, не точная оценка минимального расстояния разделения.

В просмотренных примерах P0 и P1 не выявлено очевидного ухудшения непрерывности от step=4. Однако численные max gap, centerline deviation, ширина и вариация ширины не рассчитаны. ROI visibility heuristic помечает пересекающиеся bounding boxes как ambiguous и не является доказательством игрового принятия штриха.

## 8. Ограничения и решения

1. **Расход CHALK:** step=4 подтверждён как существенно более экономичный экспериментальный профиль для протестированных геометрий. Для длинных/средних штрихов экономия около половины; для очень коротких — меньше.
2. **Delay:** между 5 и 10 ms различие по расходу практически отсутствует. Не менять delay в production только на основании этой серии.
3. **Геометрическая чистота:** V1 и V3 имеют непреднамеренные пересечения. Их telemetry и exact CHALK остаются пригодными для расхода отдельных strokes, но выводы о чистой геометрии диагоналей/поворотов требуют исправленных изолированных сценариев.
4. **Короткие штрихи:** использовать отдельную эмпирическую lookup-таблицу; провести дополнительный тест связанной полилинии против нескольких отдельных коротких strokes.
5. **Перекрытия:** V5 показывает, что визуальное слияние близких линий не означает экономии CHALK: каждый проход остаётся отдельным расходующим stroke.
6. **Визуальное качество:** обзорные PNG не заменяют заранее заданные pixel-level критерии.
7. **Production:** не менять executor defaults и не включать новый estimator. INT-007 остаётся заблокированной до полной независимой validation и утверждения safety margin.

## 9. Следующие действия

1. Подготовить исправленные изолированные геометрии V1 и V3; повторить только необходимые ячейки/повторы после проверки игровой сессии.
2. Добавить pixel-level оценку непрерывности, max gap, centerline deviation и ширины для V1–V5; вручную проверить сегментацию на сохранённых PNG.
3. Уточнить V2 lookup и сравнить отдельные короткие strokes с одной непрерывной полилинией при одинаковой суммарной длине.
4. Провести независимую проверку step=4 коэффициентов на новых DrawingPlan, не использованных в текущем fit.
5. Только после этого определить conservative safety margin и завершить INT-006.

**Неизменённые артефакты:** первичные block journals, experiment manifests, monitor reports и PNG. Этот документ — производная аналитическая сводка; raw captures не переписывались.
