## 1. Объём и источник данных

Block journal содержит 45 ожидаемых задач: 5 геометрий D1–D5 × 3 sampling profiles P0/P1/P2 × 3 повтора. В журнале все 45 задач имеют `status=completed`, по одной завершённой попытке на задачу.

Для всех 45 experiment directories найдены и прочитаны `experiment.json` и `monitor_report.json`. Проверка сохранённых данных на этом этапе выполнялась как независимый ручной разбор JSON-записей; штатная команда `chalk_int006_validation.py` ещё не запускалась на полном наборе в исполняемой среде. Поэтому приведённые ниже метрики — предварительный пересчёт, а не официальный output analyzer.

Фактический CHALK берётся только из точной игровой delta:

`actual = post_point_count - pre_point_count`

Визуальный paint meter не использовался как источник фактического расхода.

## 2. Результат проверки capture integrity

По всем 45 прочитанным парам manifest/Monitor report:

- `monitor_capture.chalk_status = exact`;
- в journal/manifest задан radius=10, `brush_radius_status=single`; полная проверка observed radius остаётся частью официального analyzer;
- число потребляющих strokes соответствует плану конкретной геометрии;
- сумма `DRAW_SAMPLE.pointDelta` по stroke ID совпадает с точной CHALK delta;
- `dropped_events`, Monitor error deltas, Bridge send-failure deltas и collector sequence gaps равны нулю;
- Monitor report связан с experiment ID и run ID из manifest;
- отсутствующих manifest или `monitor_report.json` среди 45 ожидаемых директорий не обнаружено.

Это подтверждает целостность захваченных данных по указанным проверкам, но не заменяет полный проход штатного analyzer по frozen artifact, task/journal binding и всем его fail-closed условиям.

## 5. Выводы и ограничения

1. На этих 45 captures профили P1/P2 (step=4) расходуют примерно на 21–47% меньше CHALK, чем P0 (step=2); величина выигрыша зависит от геометрии.
2. P1 немного точнее P2 по общим MAE/RMSE и имеет меньшую максимальную недооценку в текущей выборке.
3. P0 систематически завышает прогноз в большинстве проверенных геометрий. Это не повод менять коэффициенты на validation set: frozen model остаётся неизменной.
4. D5 подтверждает, что повторные проходы нужно учитывать как самостоятельные strokes; их стоимость не следует считать бесплатной из-за уже покрытой траектории.
5. D4 показывает, что короткие штрихи требуют отдельного учёта startup/lookup поведения; одной средней моделью длинных линий их описывать нельзя.
6. Все captures выполнены при radius=10. Эта серия не измеряет влияние размера кисти и не даёт основания менять radius автоматически.
7. Модель проверена только на прямых штрихах в D1–D5. Кривые, заливки, произвольные контуры и другие неподдержанные типы остаются UNKNOWN/unsupported.
