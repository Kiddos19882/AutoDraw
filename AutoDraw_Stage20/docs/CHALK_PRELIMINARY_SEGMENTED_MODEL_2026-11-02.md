# Предварительная сегментированная модель расхода CHALK

**Дата:** 2026-11-02  
**Статус:** PRELIMINARY — аналитическая калибровка; не production-модель  
**Ветка:** `feature/image-geometry-optimization`  
**Базовая метрика:** точная дельта игрового `pointCount` (`post - pre`)

## 1. Назначение и границы

Документ объединяет принятые live-измерения G1, G2, G3 и матрицы радиусов в предварительные сегменты модели. Он не подменяет первичные manifests/reports и не объявляет универсальную формулу для произвольного рисунка.

Используются:
- G1: принятый автоматизированный блок 12/12, радиус 10, `point_step_px=2`, `point_delay_ms=10`;
- G2: 18/18, радиус 10, те же параметры executor;
- G3: 27/27, радиус 10, девять сочетаний шага 1/2/4 и задержки 5/10/20 ms;
- radius matrix: 21 опыт по радиусам 1–30 на фиксированной геометрии длинных линий.

Первичные данные остаются неизменными. Подробные источники: `CHALK_GEOMETRY_MATRIX_G1_RESULTS.md`, `CHALK_GEOMETRY_MATRIX_G2_RESULTS.md`, `CHALK_G3_RESULTS_2026-11-02.md`, `CHALK_RADIUS_MATRIX_RESULTS.md`.

## 2. Базовая модель прямого штриха

Для G1 использованы 36 per-stroke наблюдений:
- горизонтальные штрихи длиной 10/20/50/100/200 logical px;
- вертикальные — 10/20/50/100 logical px;
- диагонали с приращениями координат 20/50/100 px по обеим осям; в регрессии использована евклидова длина;
- по три независимых повтора каждого штриха.

Линейная регрессия по горизонтальным, вертикальным и диагональным прямым штрихам дала:

```text
CHALK_stroke ≈ 1.765 + 0.2988 × L
RMSE ≈ 0.48 CHALK
n = 36
```

Где `L` — геометрическая длина штриха в logical px. Это эмпирическое приближение для радиуса 10 и executor `point_step_px=2 / point_delay_ms=10`, в исследованном диапазоне длин 10–200 px. Регрессия обучена на G1, а не на независимой validation-выборке; RMSE описывает остатки обучающих данных и не является гарантией ошибки прогноза.

Средние наблюдения:
| Геометрия | Длина, logical px | Средний CHALK |
|---|---:|---:|
| Горизонталь | 10 | 4.67 |
| Горизонталь | 20 | 8.00 |
| Горизонталь | 50 | 17.00 |
| Горизонталь | 100 | 32.00 |
| Горизонталь | 200 | 61.67 |
| Вертикаль | 10 | 4.67 |
| Вертикаль | 20 | 8.00 |
| Вертикаль | 50 | 16.33 |
| Вертикаль | 100 | 32.00 |
| Диагональ | 28.28 | 9.67 |
| Диагональ | 70.71 | 23.00 |
| Диагональ | 141.42 | 43.33 |

Близость коэффициентов для трёх направлений позволяет использовать эту формулу как стартовую оценку прямых сегментов в пределах указанного executor profile. Она не доказывает идентичный расход при любых углах, скорости, радиусах или transform.

## 3. Короткие штрихи — отдельный сегмент

Для коротких штрихов G1 линейная модель прямых длинных сегментов непригодна. Наблюдалась стартовая стоимость: даже штрих длиной 0 или 1 logical px расходовал одну игровую точку.

| Длина, logical px | Средний CHALK | Диапазон трёх повторов |
|---:|---:|---:|
| 0 | 1.00 | 1–1 |
| 1 | 1.00 | 1–1 |
| 2 | 2.67 | 2–3 |
| 3 | 2.00 | 2–2 |
| 5 | 2.33 | 2–3 |
| 8 | 4.67 | 4–5 |
| 10 | 4.67 | 4–5 |

Немонотонность на малой выборке не следует сглаживать в универсальную формулу. Для длины до 10 px следует использовать lookup/range по экспериментальным значениям или отдельную консервативную оценку; промежуточные длины не интерполировать без дополнительных опытов.

## 4. Sampling-профиль — отдельный коэффициент длинных линий

G3 измерял одну геометрию: шесть горизонтальных линий общей длиной 2400 logical px, радиус 10. Ниже приведены средние коэффициенты, нормализованные на 100 logical px:

| point_step_px | delay 5 ms | delay 10 ms | delay 20 ms |
|---:|---:|---:|---:|
| 1 | 56.29 | 56.26 | 86.24 |
| 2 | 29.86 | 29.92 | 57.63 |
| 4 | 15.24 | 15.21 | 29.74 |

Это сценарные коэффициенты для длинных горизонтальных линий и указанного screen transform. При задержке 5/10 ms рост шага резко уменьшает количество принятых игровых точек. Delay=20 ms существенно повышает расход. Не переносить коэффициенты G3 на короткие штрихи, диагонали, кривые, углы, перекрытия и заливки.

Для профиля step=2/delay=10 G3 дал 718 CHALK на 2400 logical px (29.92 на 100 px), что согласуется с G1 прямой моделью около 0.299 CHALK/logical px. Для step=4/delay=5/10 получено около 0.152 CHALK/logical px, но отдельная стоимость начала штриха при step=4 пока не выделена.

## 5. Размер кисти

В radius matrix средний расход на фиксированный сценарий из шести длинных линий находился в диапазоне 724–727 CHALK при радиусах 1–30; индивидуальные значения — 722–728. Систематического влияния радиуса на игровой pointCount в этом сценарии не обнаружено.

Поэтому текущая модель не умножает CHALK на радиус или площадь кисти. Радиус остаётся параметром визуального покрытия: он может изменить число траекторий, необходимых для получения нужной ширины/заливки. Это влияние следует учитывать через план покрытия, а не вводить как неподтверждённый множитель CHALK.

## 6. Перекрытие и повторное покрытие

В G2 сценарий repeated_coverage включал три повторных прохода по одной и той же траектории длиной 200 logical px и контрольный проход такой же длины по новой параллельной линии. Каждый повторный проход стоил 61–62 CHALK; контрольный — 62 CHALK.

В пределах этого сценария повторное рисование поверх уже нарисованной линии не даёт заметной экономии игрового CHALK. Для предварительного планировщика каждый повторный проход следует считать полноценным проходом, а не бесплатным покрытием. Нельзя распространять результат на любые формы наложения без отдельных испытаний.

## 7. Практическая схема предварительного прогноза

Для прямых сегментов длиной 10–200 logical px при радиусе 10 и executor profile step=2/delay=10 допустима только предварительная оценка:

```text
C_est = Σ (1.765 + 0.2988 × L_i)
```

Правила применения:
1. Суммировать стоимость каждого отдельного штриха, а не только общую длину рисунка: количество стартов важно.
2. Короткие штрихи до 10 px считать отдельным сегментом по таблице раздела 3.
3. Повторное покрытие считать повторным полным проходом.
4. Для других sampling settings применять только соответствующий сценарный коэффициент G3 для длинных горизонтальных линий, пока не проведена геометрическая калибровка.
5. Не добавлять радиус как множитель CHALK на основании текущих данных.
6. Не выдавать прогноз как точный расход: фактическая проверка остаётся за pre/post `pointCount`.

Универсальный safety margin пока не установлен. До независимой validation-маски прогноз не должен быть единственным основанием для допуска рисунка к запуску.

## 8. Ограничения доказательств

- G1/G2/G3 выполнялись при разных сценариях и контролируемых настройках; данные нельзя смешивать в одну регрессию без учёта geometry и executor profile.
- G1 regression использует 36 обучающих per-stroke значений; независимого validation набора для этой формулы пока нет.
- G2 сценарные totals без нормализации на все planned path lengths не используются как универсальные коэффициенты.
- Game Monitor trajectory остаётся `incomplete_until_verified`: coalescing может скрывать промежуточные координаты.
- Визуальная эвристика G3 сообщает 6/6 ROI с изменениями для обоих кандидатов step=4/delay=5 и step=4/delay=10, но проверяет лишь наличие изменений в широких bounding boxes. Она не доказывает непрерывность, отклонение от пути или полноту покрытия.
- PNG-файлы сохранены в первичных каталогах; их полноценный pixel-level аудит ещё не выполнен. Paint-meter image estimate имеет статус inconclusive и не используется для расхода.

## 9. Следующие обязательные проверки

1. Выполнить pixel-level аудит шести G3 captures step=4/delay=5 и step=4/delay=10: маска следа относительно blank-board reference, покрытие вдоль всей плановой линии, максимальная длина разрыва, отклонение от центральной траектории и ширина следа.
2. Если бинарные PNG недоступны аналитическому процессу, выполнить ручную проверку этих сохранённых изображений; не заменять её статусом ROI heuristic.
3. Проверить step=4 на диагоналях, коротких штрихах и поворотах либо оставить для этих геометрий базовый step=2/delay=10.
4. Получить независимый набор рисунков для validation: сравнить прогноз с точной фактической `pointCount` delta и записать absolute/relative error.
5. Только после этого определить консервативный safety margin и включать модель в production preflight.

**Решение:** модель пригодна как исследовательская калибровка отдельных сегментов. Она ещё не является production estimator и не должна переключать AutoDraw на step=4 для произвольной геометрии.
