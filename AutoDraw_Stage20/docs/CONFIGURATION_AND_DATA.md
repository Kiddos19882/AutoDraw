# Конфигурация и данные AutoDraw

## 1. Основной принцип хранения

Исходный код и пользовательские данные разделены. Приложение использует каталог `data/` рядом с исходным приложением или portable executable. В portable-сборке данные находятся внутри `AutoDrawPortable/data`.

Основные каталоги:

| Каталог | Содержимое |
|---|---|
| `data/profiles/` | Профили приложения, настройки исполнения и калибровки |
| `data/palettes/` | Профили палитр |
| `data/palettes/profiles/` | Файлы профилей палитр |
| `data/projects/` | Проекты пользователя |
| `data/results/` | Результаты операций и тестов |
| `data/results/palette_conversions/` | Результаты преобразования палитры |
| `data/results/color_scanline_plans/` | Цветные планы |
| `data/results/paint_limit_tests/` | Результаты тестов лимита |
| `data/results/brush_behavior_tests/` | Манифесты и материалы лаборатории кистей |
| `data/logs/` | Журналы приложения |
| `data/runtime/` | Вспомогательные runtime-данные |

Фактический набор создаваемых каталогов задаётся функцией `configure_environment()` в `integrated_app.py`. Часть каталогов может отсутствовать до первого запуска соответствующего инструмента.

## 2. Переменные окружения

При конфигурировании общего хранилища приложение устанавливает следующие переменные:

| Переменная | Назначение |
|---|---|
| `AUTODRAW_ROOT` | Корень приложения |
| `AUTODRAW_APP_DIR` | Каталог приложения |
| `AUTODRAW_DATA_DIR` | Корень пользовательских данных |
| `AUTODRAW_PROFILE_STORE_PATH` | Файл хранилища профилей |
| `AUTODRAW_PALETTES_DIR` | Каталог палитр |
| `AUTODRAW_TARGET_PROFILE_PATH` | Профиль целевой области |
| `AUTODRAW_EXECUTION_SETTINGS_PATH` | Настройки исполнения |
| `AUTODRAW_PROJECTS_DIR` | Каталог проектов |
| `AUTODRAW_RESULTS_DIR` | Каталог результатов |
| `AUTODRAW_LOGS_DIR` | Каталог журналов |
| `AUTODRAW_PALETTE_CONVERSIONS_DIR` | Результаты преобразования палитр |
| `AUTODRAW_COLOR_PLANS_DIR` | Цветные планы |
| `AUTODRAW_PAINT_LIMIT_TESTS_DIR` | Результаты тестов лимита |
| `AUTODRAW_BRUSH_CALIBRATION_PATH` | Файл калибровки кисти и шкалы краски |

Если путь или переменная меняются в коде, этот документ должен быть обновлён в том же изменении.

## 3. Файлы настроек и метаданных

- `app_features.json` — список заявленных возможностей, используемый при формировании build metadata.
- `data/profiles/profiles.json` — хранилище профилей, путь задаётся переменной `AUTODRAW_PROFILE_STORE_PATH`.
- `data/profiles/target_profile.json` — профиль целевой экранной области.
- `data/profiles/execution_settings.json` — настройки исполнения.
- `data/profiles/brush_paint_calibration.json` — координаты элементов управления кистью/очисткой и областей доски/шкалы.
- `data/palettes/profiles/` — сохранённые профили палитр.
- `data/results/` — создаваемые приложением результаты.

Названия файлов приведены по путям, формируемым текущей конфигурацией. Наличие каждого файла в чистом клоне не гарантируется.

## 4. Формат проекта AutoDraw

Модуль `source/preparation/autodraw_project.py` содержит операции с форматом проекта: создание/чтение, получение сводки, экспорт плана и извлечение содержимого проекта. Формат использует manifest `project.json` и набор файлов проекта, включая исходное изображение, маску/данные плана и дополнительные материалы, перечисленные в manifest.

Точные обязательные ключи, версия формата и правила проверки должны документироваться по актуальным определениям в `autodraw_project.py`. Не следует вручную менять manifest без сохранения соответствия его файловому списку.

## 5. Экспериментальные и тестовые данные

- `testImages/` — тестовые изображения.
- `testOnWin/test_new/` и `testOnWin/test_old/` — сохранённые данные калибровочных серий.
- `data/calibration/` — калибровочные данные.
- `data/results/brush_behavior_tests/` — папки запусков, манифесты, планы и изображения.
- `data/test_monitor/` — сохранённые материалы Monitor по сценариям.

Не смешивайте исходные пользовательские профили с генерируемыми отчётами. Перед переносом portable-сборки сохраняйте пользовательский каталог `data/`; при обновлении приложения пользовательские данные не должны заменяться файлами из поставки без отдельного решения.

## 6. Справочник файлового хранилища

Полный перечень путей, промежуточных файлов, шаблонов результатов и структуры проекта .autodraw вынесен в [FILE_STORAGE_CATALOG.md](FILE_STORAGE_CATALOG.md). Здесь оставлено краткое описание конфигурации и принципов хранения.

Важно различать:
- каталоги, которые создаёт единое приложение через `configure_environment()`;
- дополнительные исторические/экспериментальные каталоги, присутствующие в репозитории или создаваемые отдельными инструментами;
- файлы, включённые в Git как тестовые или демонстрационные данные.

В частности, `data/test_monitor/` и `data/calibration/` не входят в словарь путей `configure_environment()` в `integrated_app.py`; их не следует считать обязательными каталогами чистого запуска основного приложения.

## 7. Правила резервного копирования

Рекомендуется сохранять:
1. `data/profiles/`;
2. `data/palettes/`;
3. `data/projects/`;
4. пользовательские результаты из `data/results/`.

Каталоги отчётов и кэша могут быть восстановлены только в том случае, если их исходные входные данные сохранены. Git-репозиторий не заменяет резервную копию пользовательского каталога данных.
