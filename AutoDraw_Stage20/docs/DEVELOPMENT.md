# Разработка, запуск и сборка

## 1. Поддерживаемая среда проекта

Сценарии запуска и CI настроены для Windows и Python 3.11 x64. Для Tkinter требуется установка Python с Tcl/Tk. Сборка portable-приложения выполняется через PyInstaller.

Внешние зависимости разделены на файлы:
- `requirements-runtime.txt` — зависимости основного приложения;
- `requirements-build.txt` — runtime-зависимости, инструменты сборки и pytest;
- `source/preparation/requirements.txt` — зависимости подсистемы подготовки;
- `source/executor/requirements.txt` — зависимости исполнительной подсистемы;
- `source/game_monitor/requirements-smoke.txt` — отдельная зависимость локального smoke server.

## 2. Запуск исходной версии

Из каталога `AutoDraw_Stage20/`:

```bat
run_source.bat
```

Сценарий проверяет наличие Python Launcher и Python 3.11, при необходимости создаёт виртуальное окружение `.venv`, устанавливает runtime-зависимости и запускает `integrated_app.py`.

Альтернативный ручной запуск из PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-runtime.txt
python integrated_app.py
```

## 3. Запуск тестов

Из каталога `AutoDraw_Stage20/`:

```bat
run_tests.bat
```

Или:

```powershell
python run_all_tests.py
```

Отдельные тестовые наборы расположены в:
- `source/preparation/tests/`;
- `source/executor/tests/`;
- `tests/`.

Для ручного запуска отдельного набора используйте инструкции в самом тестовом модуле и соответствующие PYTHONPATH-настройки из CI workflow. Этот документ не утверждает, что тесты были запущены в рамках создания документации.

## 4. Сборка Windows portable

Из каталога `AutoDraw_Stage20/`:

```bat
build_windows.bat
```

Сценарий:
1. Проверяет Python Launcher и Python 3.11.
2. Создаёт `.venv-build`, если окружение отсутствует.
3. Устанавливает build- и runtime-зависимости.
4. Запускает общий набор тестов.
5. Запускает `build_windows.py`.
6. Запускает `smoke_test_portable.py`.

Ожидаемый каталог portable-приложения, указанный в batch-файле: `release/AutoDrawPortable/`. Исполняемый файл: `AutoDraw.exe`. Для переноса копируется весь каталог portable, а не только EXE.

## 5. GitHub Actions

Workflow-файлы расположены в `.github/workflows/`. Основной workflow `geometry-tests.yml` содержит отдельные jobs для проверок подготовки/геометрии, executor и Windows portable build/startup smoke-test. Остальные workflow относятся к отдельным измерительным/аналитическим задачам.

Триггеры, ветки, пути, версии actions и шаги определяются YAML-файлами. При изменении workflow обновляйте соответствующий раздел этого документа.

## 6. Правила разработки

- Основная рабочая ветка текущего проекта: `feature/image-geometry-optimization`.
- Не вносить изменения в `master`, если отдельная задача явно не разрешает это.
- Не хранить пользовательские секреты, токены и приватные данные в репозитории.
- Не добавлять пользовательские абсолютные пути в переносимые профили.
- При изменении формата данных обновлять документацию формата и соответствующие тестовые фикстуры только в рамках отдельно согласованной задачи.
- При изменении интерфейса или точек входа обновлять каталог компонентов.
- При изменении зависимостей обновлять документацию и соответствующий requirements-файл.
- Значимые изменения фиксировать отдельными коммитами с понятными сообщениями.

## 7. Проверка документационных изменений

Для документационных коммитов проверяйте:
- корректность относительных Markdown-ссылок;
- соответствие путей реальному дереву репозитория;
- отсутствие утверждений о запуске тестов, если они не запускались;
- отсутствие изменений в исходниках и пользовательских данных, если задача ограничена документацией.
