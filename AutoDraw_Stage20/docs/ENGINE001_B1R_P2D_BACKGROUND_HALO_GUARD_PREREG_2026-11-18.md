## Задача, подтверждённый E1 baseline, визуальная оценка

Пользователь отметил на `C_096 NEAREST` и `C_192 NEAREST` одинаковую **светло-серую лишнюю область над верхней прядью волос** (в оригинале там почти белый фон), при этом «в основном визуально оба варианта хороши пока что». Это **предварительно положительная** оценка обоих вариантов, **НЕ** окончательное принятие. Исследование E1 source оригинал/flat/P2B/C_096/C_192 ZIP artifact14408783882: logical original bright pixel около (80..86, 6..10), например original `(254,254,252)` vs original-derived J_FINE flat `(227,226,221)`. В P2C `NEAREST` этот flat-краситель буквально сохраняется, хотя в исходном фрагменте он отсутствует. Поэтому **основной изъян возник в J_FINE flat-region medoid**, а не только в K_DETAIL и не kmeans. Изолированный prereg point ROI logical 150x240 `[x0=76,y0=4,x1=91,y1=19]` вокруг отметки; этот ROI — только ранний пользовательский diagnostic, не обучающая маска и не разрешение специфического глобального костыля по координатам. В предыдущем исходном ZIP baseline **27** original-bright false-dark logical pixels в ROI для C_096 и C_192 (source min RGB≥245; candidate meanRGB source-candidate≥12). Эти ROI, параметры и baseline записаны **до** запуска P2D. Результат старого P2C заморожен, никакие thresholds P2C не изменять.

## Протокол P2D — two ablations across two frozen P2C budgets

Original: `AutoDraw_Stage20/testImages/wV6VeZI9S1Y.png`, original RGB 200x320, **SHA256 `07cc4568cb5e90d9514bc6f6c2112fee623f87f8fd0cea02fa517b04108e502a`** fail-closed. В каждом новом P2D run в памяти заново построить P1 A_SOFT full protected, J_FINE original-only SLIC900/compactness6, original member J_FINE medoids, P2B `K_DETAIL` source-only exact mask и обе P2C compressed ink palettes `C_096` / `C_192` (fixed seed1729, 16 iterations, medoids source-ink). Переиспользуются **исключительно оригинал и математические функции из тестовых source-only runners**, запрещено использовать существующие P2B/P2C PNG, NPY, JSON как вход или восстанавливать маску из них; исторические G32/V44/M1 не участвуют даже как targets. Source and run SHA, исходные pixel/cluster ledgers, reconstruct verification. P2C original-only baseline re-run — **read-only control** в том же run; frozen P2C actions/metrics не меняются.

Original near-white raster `bright = (minimum RGB channel≥245) AND ((maximum-minimum) RGB channel≤18)`, full original200x320. `L_src = mean original RGB`, `L_flat = mean J_FINE flat RGB`. `source_false_gray = bright AND ((L_src-L_flat)≥12) AND (L_flat≤239)`. Крупные настоящие тёмные линии не удовлетворяют условию `bright`. `source_white_swatch = original[0,0]` при проверки, что пиксель сам `bright`; candidate всегда source RGB, не произвольная новая краска. Candidate guard действует только на **не ink** пиксели `source_false_gray & ~K_DETAIL_ink_mask`; исходную геометрию `K_DETAIL` и каждый назначенный P2C ink RGB сохранять exact. Заменить в *полнорезолюционном RGB P2C кандидате* затронутые RGB на `source_white_swatch`, затем сравнить честные visual LANCZOS и discrete NEAREST logical 150x240. Не рисовать новое outline, не редактировать 32-color palette. Сжатая палитра P2C плюс максимум один источник-white swatch, full+NEAREST source color count ≤ same-run P2C full count + 1; LANCZOS создает интерполяционные цвета и не является игровой palette.

**Две фиксированные стратегии пространственной поддержки, кроме которых всё идентично:**
- `D_BORDER`: `source_false_gray` и оригинальная `bright` 8-связная component, которая касается любого края исходного изображения 200×320.
- `D_COMPONENT24`: `source_false_gray` и оригинальная `bright` 8-связная component размером ≥24 source пикселя, включая внутренние области с достаточной поддержкой. Ни одна компонента не создаётся из исторического контура или G32.

Проверяются четыре связки: `C_096+D_BORDER`, `C_096+D_COMPONENT24`, `C_192+D_BORDER`, `C_192+D_COMPONENT24`. Пустой guard на source input / wrong SHA / RGB dims / wrong ink bool shape / no bright source pixel at top-left / wrong variant → fail-closed. Separate debug binary mask for each guard, counts by source component and source row-major selected provenance. Не выбирать лучший по порогам после исследования.
