# ENGINE-001 / B1-R-P3E — статическая достижимость палитры 128 игровых цветов и маршрут выбора цвета

**ID:** `ENGINE001_B1R_P3E_ENGINE128_COLOR_UI_AUDIT_V1`. **Дата 2026-11-18. E0 prereg ДО новых скриптов/CI.** Исследование только E1/E2/E3 на исходниках, не E4 живой игры. Предыдущие P3B A/B (DEC-037) и P3D E_SOBEL90/F_SOBEL90_LAB12 (DEC-038) одобрены для продолжения в объёме ручной визуальной оценки, но не валидированы нативной кистью/доступностью цветов. Ни один вариант не отменять и не объявлять production.

## Вопрос и baseline

В JS движка `AutoDraw_Stage20/gameEngine/main.min_653f95bc.js` pinned Git blob SHA1 `46cc74de00b6cb5d207b1e1a2ffcd81613b6d388`, ровно 128 уникальных цветов объявлены в `PainterPopup.createElaborateEasterEggs` и `oldCreateElaborateEasterEggs`. Входной скриншотный снимок (ф) `AutoDraw_Stage20/data/palettes/browser_palette.json` blob `461b5f3725b9b79888ad36e807b3cf4c9e445e98` содержит **32** образца со screen-coordinates от 2026-10-26, НЕ полную карту реальных доступных цветов и НЕ действующую калибровку исполнителя.

**Новый независимый аудиторский E1 контроль (до prereg кода):** в ZIP [P3D CI44290366441/artifact14420417870](https://github.com/Kiddos19882/AutoDraw/actions/runs/44290366441/artifacts/14420417870) SHA256 `9441d2d0b68672bc5fdbef5edf68f4560fecac3beec1fb37c2c4fb28880b8ca1`, прочитаны `report.json`, `*_P3B_M0_INDICES.png` и соответствующие engine RGB; сопоставление с screenshot JSON32 по точному `#RRGGBB` показало для каждого P3D E/F **32 реально используемых engine swatches, только 5 совпадают с 32 screenshot, 27 отсутствуют в screenshot JSON**, около **12,559–12,642 /36,000 (34.9–35.1%) пикселей** назначены оттенкам вне screenshot32. Они имеют прямое происхождение из engine128, но **их физическая доступность в игре UNKNOWN, а не FAIL**.

## Исследовательские задачи и критерии E1/E2/E3

1. Чтение ТОЛЬКО pinned gameEngine JS blob, fail-closed на hash/размер drift. Применить существующий `run_engine001_b1r_p3b_engine128_adaptive32.read_engine_palette`; не писать второй parser 128 цветов. Открыть ограниченные контексты minified JS для `createElaborateEasterEggs`, `oldCreateElaborateEasterEggs`, `_isPainterExtend`, `EggColorIcon`, `eggColorChangedHandler`, `setColor`. Сохранить число совпадений и короткие контексты, без экспорта 4.86 МБ в чат.
2. Проверить строго: 128 уникальных 24-bit RGB и WHITE6, old/new массив идентичен, все 32 скриншотных RGB — реальные engine swatches, JSON32 snapshot SHA pinned; предоставить индексную таблицу engine128 vs screenshot32, без объявления координат screen32 актуальными.
3. Отделить **static declaration**, **conditional UI gating** (`_isPainterExtend`, кнопки/меню), **color-selection event path** и **actual active game runtime reachability**. Первые три оцениваются E1 по коду с ограниченными excerpt; последний остаётся `UNKNOWN_E4_NOT_RUN`, пока нет независимого runtime capture. Нет автоматического открытия «пасхальной» палитры в живой игре, никакого bypass/click через устаревшие координаты.
4. Output единый JSON + bounded TXT + SHA256 каждого файла в одном GitHub Actions ZIP, pinned SHA/CI run ID; отдельные синтетические E2 тесты на shape/fail-closed/скриншотную палитру; фиксировать CI PASS только для соответствующего SHA. Не переименовывать CI pass в palette runtime PASS.
5. **Gate на переход к нативной покраске:** для каждого из фактически требуемых 32 swatches подтверждён валидный способ UI выбора/установки цвета в реальном экземпляре игры, безопасная калибровка координат и наблюдаемый color echo/board color; если хотя бы один отсутствует, `BLOCKED_COLOR_UI_ACCESS`. Реальный E4, E5, coverage/leakage, Stage6, Bridge/Monitor, exact CHALK `post.pointCount-pre.pointCount` на этом этапе НЕ ЗАПУСКАЮТСЯ. Не использовать старые G32/V44/M1, frozen P3B/P3D как генеративные входы; сравнение frozen P3D только audit provenance.

**Статусы на момент prereg:** DEC-038 ручное визуальное P3D ACCEPTED только для продолжения; E1 аудит snapshot32 vs P3D PASS на ограниченном offline наборе, E2/E3 нового P3E NOT_RUN, игровая доступность engine128 UNKNOWN, физический вывод game32 NOT_VALIDATED. Следующий шаг — E2/E3 static routing audit, затем решение о самом минимальном безопасном E4 протоколе с подтверждением доступности runtime.
