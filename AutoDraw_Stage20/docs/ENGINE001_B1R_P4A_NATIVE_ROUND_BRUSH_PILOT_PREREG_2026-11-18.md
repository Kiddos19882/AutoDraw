## Цель, вопрос, baseline

**Цель:** установить первые проверяемые геометрические параметры native Egret/BoardPane кисти для построенных заново от оригинала E/F карт P3D, не создавая новый production-planner и не вмешиваясь в игру. Проверка маленькой выборки отдельных настоящих следов кисти, не всей картины; **не заявлять полный coverage/CHALK/качественный готовый рисунок**. Первая выборка — **один** одобренный source P2D `C_192_D_COMPONENT24`, оба P3D E_SOBEL90/F_SOBEL90_LAB12, прочие три source комбинации не отменены и переходят в расширенную отдельную серию только после этого pilot. Точное исходное изображение (ф) `AutoDraw_Stage20/testImages/wV6VeZI9S1Y.png` SHA256 `07cc4568cb5e90d9514bc6f6c2112fee623f87f8fd0cea02fa517b04108e502a`, source logical150×240, board460×240, вставка x=155, archived native backing1380×720, scale3. Static engine bundle JS git blob `46cc74de00b6cb5d207b1e1a2ffcd81613b6d388`. Нативный renderer `tests/game_renderer_reference.js` + текущий `run_engine001_complex_holdout_v5.native_batch(...,"renderComplexHoldoutColorProbe")`; verify exact renderer path and SHA in runner before use. E3 offline archived BoardPane is not E4 game.

**Переменные:** method E/F, width∈{2,4,6,10} и две ориентации HORIZONTAL/DIAGONAL (для 1 цвета с наибольшим безопасным внутренним 4-connected регионом, не WHITE6; если нет доказуемо безопасной области — `BLOCKED_GEOMETRY`, не подменять). Выбрать тот же идентификатор цвета для E и F **из пересечения** обеих M0-derived карт; выбрать детерминированные 2-точечные отрезки с внутренним запасом≥(width/2+2) логических пикселей на основе дистанции до НЕ-своего цвета в обоих вариантах; если хотя бы один отрезок не подходит обеим — fail-closed, без ручной коррекции после результата. Каждый stroke имеет 2 точки, цвет точно выбранного engine128 RGB, ID `icon-N`, width реальной игры (2,4,6,10). Всего 8 strokes/variant, не более16 отдельных native и composites; те же пути между E/F. Исходный P3D каждый раз пересчитывается по текущему P3D pipeline **из оригинального RGB, без архивных G32/V44/M1/P3D pixels**. Не импортировать frozen ZIP как генеративный ввод. Допустимо использовать P3D-provenance report как baseline для сверки SHA/count, не для генерации.

**Независимые gates** до работы с изображением:
1. Pin source JS original, same-run P3B/P3D methods, all P3B/P3D source-quality gates, selected32 actual engine swatches+WHITE6, accepted P3D status, AND source E/F masks indexed maps. No imports from old G32/V44. Synthetic regression of original-to-board x+155, y unchanged, board 460×240, no use stale screenshot32 coordinates.
2. Stroke metadata stable and valid per native `renderComplexHoldoutColorProbe`: allowed width, 2 points, original-index-derived nonwhite RGB, point coords x∈[155,304], y∈[0,239], ids unique, ≤5900 vertices and ≤3000 strokes; source footprint mathematical search labeled **MODEL_ONLY** for proposal, not for PASS.
3. Native Egret/WebGL renderer returns actual per-color RGBA `(720,1380,4)`, blank scene/no-stroke control and full composite. Record alpha24 and128. Each proposed stroke must produce >0 real native alpha pixels; actual ink outside its owner target beyond **3 logical pixels** =0 at alpha24 (distance measured on backing3), plus at alpha128 separately diagnostic. Accept only if all native source/renderer identity, nonzero pixels, bounds and leakage PASS. Do not assert full-image coverage of ≈4.9k islands as this is a sparse pilot.
4. Separate metrics coverage *of only pilot local target bounding boxes*, not global 99% full quality. Never call E3 native "live CHALK"; exact run-bound CHALK requires separate E4 and independent E5. No run on user PC, no Stage6/executor/default writes; no screenshot32 color-coordinate use.
5. On conflict or technical failure emit `FAIL/BLOCKED`, preserve original captures and logs; no automatic rerun with modified thresholds/geometry. Manual review of native RGB and source/owner masks for E/F required even if geometrical gates pass.
