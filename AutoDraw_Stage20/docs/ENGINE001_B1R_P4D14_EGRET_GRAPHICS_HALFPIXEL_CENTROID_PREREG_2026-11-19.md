# ENGINE-001 / B1-R P4D14 — математический сдвиг центра кисти в Egret 5.4.1

**E0 prereg 2026-11-19, ДО разработки P4D14 runner/tests/CI.** Experiment ID: `ENGINE001_B1R_P4D14_EGRET_GRAPHICS_HALFPIXEL_CENTROID_MODEL_V1`. По прямому запросу пользователя: сначала поиск в сети, затем попытка объяснить с помощью математики неполную переносимость кисти между координатами. Исходные B1-R P4D3/P4D4 raw, production, Stage6 executor, default brush/CHALK, master, frozen game bundle не менять.

## Исследование исходного кода до протокола

В [публичных исходниках Egret 5.4.1](https://github.com/egret-labs/egret-core/blob/master/package.json) (`version:5.4.1`) обнаружено:
- [`src/egret/player/rendering/CanvasRenderer.ts`](https://github.com/egret-labs/egret-core/blob/master/src/egret/player/rendering/CanvasRenderer.ts), метод `renderGraphics`: для `lineWidth===1 || lineWidth===3` выполняется `context.translate(0.5,0.5)`, затем `stroke()` и обратный `translate(-0.5,-0.5)`; другим widths специального смещения нет. `context.lineCap=...round` при original default.
- [`src/egret/display/Graphics.ts`](https://github.com/egret-labs/egret-core/blob/master/src/egret/display/Graphics.ts) `setStrokeWidth`: разная нулевая/правая логика bounds для width1/3; `updateNodeBounds` = `Math.ceil(max-min)`.
- [`src/egret/web/rendering/webgl/WebGLRenderer.ts`](https://github.com/egret-labs/egret-core/blob/master/src/egret/web/rendering/webgl/WebGLRenderer.ts) `renderGraphics`: промежуточный Canvas для graphics, `width2=Math.ceil(width*canvasScaleX)`, масштаб `canvasScaleX*=width2/width`, `translate(-node.x,-node.y)`, перенос в WebGL texture. Значит буквальная математическая capsule без Canvas2D/texture не является точным игровым отпечатком; `gl.lineWidth` не является правильной прямой моделью.
- [OpenGL spec §3.1](https://registry.khronos.org/OpenGL/specs/gl/glspec20.pdf) идеализирует инвариантность примитивов при **целочисленном переносе в window coordinates**, но Egret рисует Graphics через Canvas2D/texture, и идеализированная спецификация не доказывает сохранение RGBA в его составном пайплайне.
- **Независимый до-экспериментальный E1 по frozen P4D3 raw ZIP14480461909, 480 real native scenes:** alpha-weighted центр первой копии W1 примерно +0.5/+0.5 logical, W3 примерно +0.5/+0.5; W2,4..10 около нуля. Это *предварительный анализ* без нового E2/E3. P4D3 repeated 480/480 identical, integer translations 292/480 RGBA-equal, P4D4 snap1/256 256/480. Эти цифры нельзя переименовывать или считать доказанной единственной причиной.

## Цель и математические формулы

Исходные game-backed stroke endpoints: `p0=(cx+0.25, cy+0.375) ± (length/2)(cos angle, sin angle)`, normal, rounded, width1..10, реальные `BoardPane.redraw` + Egret5.4.1. На 3× backing RGBA измерить **альфа-взвешенный центр** отдельно каждого из10 независимых штрихов. Пусть `A_ij` — native alpha, `SCALE=3`, `r=(x_i+0.5, y_j+0.5)/SCALE` в логических coords. Тогда `C_native = sum(A*r)/sum(A)`, `S=sum(A)>0`. Сравнить две заранее зафиксированные гипотезы:
- **M0 (наивная)**: `C0 = (p0+p1)/2` по двум осям.
- **M1 (из исходников Egret)**: `C1=C0+(h,h)`, где `h=0.5` только при `width in {1,3}`, `h=0` для всех остальных ширин.
- Ошибка `e0/e1 = sqrt((C_native.x-C_model.x)^2+(C_native.y-C_model.y)^2)` в логических пикселях. Суммарные mean, median, max/95p по widths1,3 отдельно и всем другим, per-case. Это центр отпечатка (не модель полной границы/alpha). **Формула для canvas backing:** `x_physical=3*(x_native_logical)`; относительное различие модели `3*0.5=1.5` backing pixel, но pixel-center convention `+0.5` применяется при измерении weighted center. Искомый 0.5 shift НЕ объясняет автоматически нетождественность пространственно перенесённых копий.

## Строгий E3 дизайн

- Повторно через unchanged `P4D3.build_primary` source blob `3437a9326b381d9c94d6ade80059d40adf233d09`, unchanged `game_renderer_reference.js` Git blob `76d950e0a8911888a9df3b675b866519ecf7bba4`, engine Git blob `46cc74de00b6cb5d207b1e1a2ffcd81613b6d388` выполнить **160** оригинальных P4D3-like настоящих BoardPane/WebGL native scenes: все widths1..10 × angles `(0,15,30,45,60,90,135,165)` × lengths `(4,34)` =160. В каждой сцене десять копий + один control + десять overlaid в 12 позиций, как P4D3. Без новой quantization/огрубления, предел кадров настоящий test harness.
- **Repro controls**: повторить ещё 10 сцен width1..10 при angle0,length4 с точными теми же координатами и проверить повтор raw RGBA побайтово. Плюс нативный blank. **Всего 171 native PNG**; сохранить все E3 исходники, plans, append-only JSONL, actual alpha and center coordinates, RGBA exact/alpha24 XOR across translations, duplicate controls, SHA manifest, HTML-compatible PNG visual plot of model residual vs width and representative cells.
- **H1:** для widths1 и3 исходниковая модель M1 даёт меньшую aggregate mean native-centroid Euclidean error, чем M0. **H2:** для widths2,4..10 модели тождественны и error не меняется. **H3:** 160 scene integer-translated RGBA equality **не станет 160/160**, даже при правильном предсказании центров, подтверждая наличие другого source-dependent edge/anti-aliasing эффекта. Если H3 false — сохранить. Native alpha24/XOR и MAE измерить отдельно; не выдавать совпадение центров за пиксельную эквивалентность.
- E2 тесты pure math: exact ±0.5 conditional, centroids for synthetic alpha masks and physical-to-logical transform, blank reject, per-width deterministic means, no reliance on source color or old contour. Historical P4D3 and P4D4 E3 results immutable. Native E3 acceptance только при завершённых171 scenes, original renderer/browser schema, zero blank, successful SHA and unchanged pins; scientific H1/H2/H3 statuses отдельны и могут FAIL.
- **Границы применимости:** archived Firefox/Windows Egret native capture — E3, не E4 actual running game; не доказана точная модель Canvas2D антиалиасинга, alpha alpha1/24 pixel footprint, нет полной P4D13 ROI проверки качества, нет exact run-bound CHALK или E5 независимой научной validation. Итог при подтверждении M1 — отдельная экспериментальная математическая поправка, НЕ production default. Для переноса дальнейший шаг — предсказать Canvas2D edge raster and intermediate texture rounding на исходных координатах, сравнить raw RGBA с P4D3 reference.
