## 1. Развести математическую точность, физический эффект и визуальную приемлемость

- **Физическая точность / научные E0:** старые zero-foreign, G3 usefulness >=90%, source-owner alpha/RGB и иные заранее замороженные критерии сохраняют исходные PASS/FAIL. S3v2q **Q1 PASS**, **20 true second-`stroke()` lower-owner RGB pixel changes** и G3 `7653/8633=88.65%` **Q2/Q4 FAIL**, C0 32/40 Canvas+13/40 WebGL FAIL. S3v2p original 17 owner harms/G3 88.90% FAIL, P4D18 original protected E/F quality FAIL. Никакой новый тест не переклассифицирует эти outcomes.
- **Новая отдельная *кандидатная* визуальная политика для будущей validation:** изменение RGB на 1–2 байта *может* быть простительным только при явном owner-consistent исходном и конечном цвете, стабильной alpha, отсутствии накопления/ореола и дефекта контура; **не является автоматическим допуском для protected foreign/white, critical contour и глаз/лица/кистей**. Порог 2 — **DIAGNOSTIC CANDIDATE**, а не новый утверждённый safety hard gate. Изменение protected foreign>0 по старым E0 всегда FAIL; будущий новый quality gate требует отдельного E0 и решения. Отсутствие заметности не выводится из `max channel<=2` без реальной проверки и контекста.
- **Визуальная оценка будущего whole-image:** coverage физическое + logical 5/9,7/9,9/9; разрывы alpha0 и белые holes; защищённый original-white, ложные островки цвета; silhouette, face/eyes/hands, contour continuity; локальный perceived difference / ΔE как дополнение, не замена защищённых gates; foreign owner, дальний leakage <=3 logical px. Не подменять original-RGB target моделью.
- **Планировщик:** хранить `PASS_NATIVE`, `UNKNOWN`, `FORBIDDEN` отдельно от научной маски; неопределённый pixel-safe action запрещён до native backstop. Не менять game executable defaults, Stage6, Bridge, Monitor, мастер-ветку.

## 3. Прекращение бесполезных исследований («без фанатизма»)

1. **Одно E0 → одно новое семейство настоящих Egret испытаний → один итоговый отчёт → решение**, а не новые v2x ради ещё одного 1-byte отличия. Повтор/новая версия только при явной технической невалидности или *новой, практически значимой* гипотезе; исходный negative остаётся.
2. Если выявлены только source 1–2 RGB bytes, alpha unchanged, нет накопления в bounded sample и нет визуально значимых дефектов, прекращаем исследовать низкоуровневое округление и переключаемся на *physical coverage/holes* в S5. Это **не** означает scientific pixel-safe PASS/нулевые foreign owner.
3. Если есть alpha0 отверстия, видимый leakage, ухудшение outline/protected-white/face/eyes, либо накопление >2 — изучаем **только этот** риск через новый E0, не исправляем исходный E0 и не расширяем вслепую допуск.
4. Технический CI PASS ≠ scientific PASS ≠ game E4/E5. Для каждого S3 опыта сохранены оригинальные pixel negatives, исходные plans, raw PNG, SHAs, calibration/hash proof, browser version, experiment/run ID. До разрешённого производственного внедрения нужны source-quality и independent validation.
5. Новая идея, которой ещё нет в E0, не добавляется задним числом к уже замороженному корпусу; текущий bounded S3v2r не используется для tune+holdout одновременно.
6. **Приоритет ресурсов:** (а) реальные пробелы и целевые пиксели, (б) непрерывность контуров и protected regions, (в) количество ненужных штрихов. WebGL-specific новые тесты — только если возвращается наблюдаемый Canvas→WebGL mismatch, а не профилактически.

## 4. Первое действие и ограничение разрешения

**FIRST:** отдельный новый S3v2r E0 — true native Egret small bounded design *contrast and repeat*, original per-stroke pre/post, ref colors and fixed alpha0-isolated-top owner region, independent exact WebGL controls, all per-pixel negatives, original G3 past failures preserved. No new main planner, full repaint, S4 BLIND, production/margin changes. Ключевой вопрос: остаётся ли реальная ошибка «невидимым RGB» при нескольких одинаковых верхних штрихах и разных цветах первого owner, или растёт/затрагивает alpha и чужую зону. Архивировать отрицательные даже при научном FAIL.

**NEXT after S3v2r:** документировать один explicit decision, затем вернуться к установленной очередности без бессрочных tests of rounding. На этапе S5 применять проверку real Egret coverage/gap/overdraw и оптимизировать полную исходную E/F уже по визуально значимым метрикам. Старые E/F protected failures не потерять.
