## Непосредственная причина блокера, до нового эксперимента

В архивном S3 [artifact14604987986](https://github.com/Kiddos19882/AutoDraw/actions/runs/44683117471/artifacts/14604987986) исходный пустой PNG \`S3_REAL_EGRET_BLANK.png\` SHA256=\`a710a1d94ce39b2533c672667b456095295185fb0cd8c5a9904bec6313346a96\`. Из неудачного [S3v2 artifact14606465655](https://github.com/Kiddos19882/AutoDraw/actions/runs/44684709364/artifacts/14606465655) \`S3V2_REAL_EGRET_BLANK.png\` SHA256=\`7ec762312ad50033fba5f33b60d8526eaa1e131caad351a376abc724cb2e4a30\`. Обоих размеров 1380×720 и оба полностью RGBA=(0,0,0,0). Сравнение исходных ZIP показало одинаковые PNG signature/IHDR/IDAT/IEND байты и **ровно одну** разницу: PNG ancillary chunk \`deBG\` length16: \`C7A01DCE0C0A103F\` против \`587A190515BA6635\`, с новыми CRC. Этот служебный nonce — вероятная причина байтового дрейфа; пока подтверждено только для одного blank. Никакого утверждения о pixel-exact для 80 новых сцен, пока они не нарисованы.

## Замороженная новая техническая эквивалентность; не ослабление научного H1

S3v2b применяет **строго один прозрачный для содержимого исключаемый PNG-чанк** и ни один иной: для 91 пары parent/current real WebGL PNG валидировать PNG signature, CRC всех chunks, тот же порядок и количество chunks, одинаковые IHDR и **побайтово идентичные IDAT payload(s)**, все остальные chunks идентичны; единственное разрешённое отличие — один \`deBG\` с длиной **ровно16 ASCII hex**, присутствующий один раз на одинаковой позиции, корректный CRC. После этого независимо декодировать два PNG в \`uint8 RGBA\` 1380×720 и требовать абсолютно идентичные RGBA пиксели. Если любой IDAT/pixel/формат/иной metadata chunk отличается — \`BLOCKED/FAIL\`, не ретюнить на результатах. Сохранять оригинальные сырые SHA256 и оба исходных оригинальных PNG, не удалять \`deBG\` из raw, не перезаписывать замороженный архив.

Изначальное требование S3v2 \`raw byte equality\` не пройдено и не переписывается: в новой S3v2b версии документировать \`original_S3v2_raw_byte_gate=FAIL\`, \`S3v2b_validated_deBG_equivalence\` отдельно. Нельзя применять этот способ к Canvas PNG intermediate против final WebGL (это разные стадии), только к повторяемости исходного **final** WebGL PNG.
