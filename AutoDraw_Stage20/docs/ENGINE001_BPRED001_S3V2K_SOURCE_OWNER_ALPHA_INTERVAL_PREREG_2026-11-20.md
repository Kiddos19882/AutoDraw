## 3. Two preregistered physical-alpha representations, no trained lookup table

Define byte alpha (A) and normalized, unobserved physical alpha interval (a in [max(0,A-0.5), min(255,A+0.5)]/255). In particular, isolated observed (A=0) represents **possible** physical alpha (0≤a≤0.5/255), not guaranteed (a=0). This is a **hypothesis under nearest-byte rounding**, not an established exact Firefox alpha coverage bound. Use original owner known source color (C_{owner}) for weak coverage even if the independently exported alpha0 PNG stores RGB=(0,0,0). Saturated (A=255) stays a small interval, not assumed exact alpha=1 unless separately measured.

Predefined candidates:
- **I0 / byte-only negative control**: original straight `B0`, explicitly treats top source alpha0 as 0 and predicts no owner change.
- **I1 / interval `source-over`**: for every pixel propagate interval bounds of the two original owner's alpha through (a_o=a_t+(1-a_t)a_b); per channel in premult form (P_o=a_t C_{t,owner} +(1-a_t)a_b C_{b,owner}), source color channel (C) normalized /255. For comparison with original straight native PNG, divide by (a_o) only if its *entire* admissible interval excludes0; otherwise label `UNKNOWN_LOW_ALPHA`, never fake a confident RGB. Obtain conservative extrema over all four input alpha interval endpoint combinations and include fixed **±2 output RGB bytes** and **±1 output alpha byte** for unknown byte/coverage conversion, clipping to0..255. These ±2/±1 are **uncertainty envelope padding only, NOT new permitted actual error or source-owner acceptance threshold**. Never modify original C0/H1 calculations; no width/angle-specific fitted weights, posterior selection, or independent colour blending calibration.
- **I2 / geometry-gated abstention control**: for each actual physical board pixel, map center to logical coordinates `((x+0.5)/3,(y+0.5)/3)` and compute exact point-to-*original top stroke line-segment* Euclidean distance using the original two endpoints, not an idealized simulated brush. Only when this distance is **strictly greater** than `(top source width/2 + 3)` logical px, and independent observed top byte alpha0, classify `UNCHANGED_CANDIDATE` (a *research geometric hypothesis*, not established true native bound). Otherwise if alpha0, output RGB interval width>2 bytes, or output alpha interval includes0, classify `UNKNOWN` (never `ADMISSIBLE`). This distance margin is preregistered as a conservative diagnostic feature, **not** a reinterpretation of the existing far-leakage<=3 logical px image-quality gate. The previous unimplemented draft rule requiring an interval padded by ±2 to have width0 would be vacuous and is explicitly superseded **before any S3v2k code or tests**, with its former Git blob retained in commit history. Any observed changed owner beyond this fixed distance is `FALSE_SAFE` and invalidates the candidate, rather than allowing a posthoc margin increase.
