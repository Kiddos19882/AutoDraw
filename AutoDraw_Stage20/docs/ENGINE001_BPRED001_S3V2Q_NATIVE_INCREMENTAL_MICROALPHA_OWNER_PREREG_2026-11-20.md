Question: Does the original `stroke()` operation change **actual already painted bytes within the same live Canvas** at physical positions where isolated second-owner alpha exports as zero? S3v2p compared independent lower/upper scenes at final image, not true same-stroke `pre -> post` on the live original main Canvas. One might see genuine changed bytes from hidden sub-byte coverage or re-quantization, or only an earlier event/readback mismatch. This experiment captures the direct pre- and post-call observations without changing the original renderer.

Frozen alternatives:
- **A (observed incremental alteration):** for one or more true native main events after the original first owner, pre-vs-post `getImageData` RGB/alpha differs at coordinates where isolated upper-owner post image has alpha0, and lower alpha>0. This proves observed incremental alteration during that original stroke; it does **not** prove hidden internal subbyte coverage, blend equation or intent.
- **B (no observed incremental alteration):** first-owner and final-original differ when scene-external exports compared, but no within-event difference at such coordinates, suggesting event baseline/different observation epoch or other original behavior rather than observed incremental change. Record the discrepancy, no source-safe conclusion.
- **C (unstable repeated read):** two consecutive `getImageData` observations *after the same stroke with no draw between* differ. Then post-call causality is ambiguous, scientific result BLOCKED for affected scenes; no dropped cases.
- **D (instrumentation perturbation):** an uninstrumented genuine original WebGL replay differs from instrumented result on fixed 162×162 RGBA ROI: technical BLOCKED, no safe causal finding.

The Canvas specification explicitly permits lossy premultiplied ↔ unpremultiplied RGB conversion; `getImageData` and PNG are exported observations rather than access to internal fractional coverage (https://html.spec.whatwg.org/multipage/canvas.html). No inference of internal browser integer/float storage is permitted merely from an exported one-byte delta.
