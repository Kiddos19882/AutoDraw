## Why this one follow-up instead of another full RGB rounding search

We know native original Egret main Canvas second `stroke()` sometimes changes prior-owner RGB by1–2 even where isolated top exported alpha0, stable `getImageData`, no event gap; internal fractional source or premult precision UNKNOWN. User accepts small changes **only if visually irrelevant**. The new study asks if an unchanged top stroke repeated 8× over different genuine colored lower-owner substrates **accumulates observable owner damage**, changes alpha, or causes >2 RGB byte deviations from its source baseline. This is a *risk-accumulation test*, **not a test of which exact internal browser quantizer exists**. Do not fit rounding or relax frozen historical hard gates.
