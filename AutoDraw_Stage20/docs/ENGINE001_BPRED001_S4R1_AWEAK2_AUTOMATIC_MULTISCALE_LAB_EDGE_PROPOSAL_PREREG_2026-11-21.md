## Ровно один источник-автоматический кандидат

Вход: оригинальный RGB/alpha произвольного размера, существующий `generic_source_maps(original_rgba)` и `original_source_region_uncertainty(original_rgba, source)` без модификаций; никаких hardcoded ROI/лиц/игровых цветов. Прежде всего AQA1 проверяет 4/4 SHA-блоков original и 4/4 загруженных человеческих A PNG+JSON, E0 blob-фиксацию AWEAK1 и AWEAK2. Ни train, ни segmenter на A, ни ручных корректировок, ни угадывания owner128.

**Кандидат (написать именно так):**
1. `Lab = skimage.color.rgb2lab(original_RGB/255)`, каждая из трёх Lab-координат обрабатывается `scipy.ndimage.gaussian_filter` с `sigma=(sigma,sigma,0)`, `mode=reflect`. ТОЛЬКО два масштаба, `sigma=1.0` и `sigma=3.0` исходных пикселей, оба объявлены до измерений.
2. `mag_sigma = sqrt(sobel(L)^2+sobel(a)^2+sobel(b)^2)` с `skimage.filters.sobel`; численная защита: `mag <= 1e-9` считается нулём (это не визуальный gate). На каждом масштабе отдельно `threshold=90-й процентиль strictly positive mag`; если positive нет, edge mask пуст; иначе `mag>=threshold`. 90-й процентиль наследует исходный P1/Sobel90 диагностический подход, не новый порог игры и не выбран по текущим AWEAK1 измерениям.
3. Объединить два бинарных edge, расширить `scipy.ndimage.binary_dilation(..., iterations=1)` (4-соседняя структура по умолчанию), получить `source_multiscale_warning`. Новая **предложенная** `protected_trial = old_protected | source_multiscale_warning`. `hypothetical_core_trial = existing_SLIC_geometric_potential_core & ~source_multiscale_warning`. Сразу проверить `old_protected subset protected_trial`, `core_trial subset old_core`, `core_trial within old UNKNOWN`, `original source RGB/alpha unchanged`, `source owner=MISSING`, `stroke_admission=FORBIDDEN`. **Ни одна единица core_trial не становится безопасной для stroke!**
4. Никакой новой сегментации цвета/смешивания/палитры/ручного RGB-equivalence GT; входная human `A` не влияет на построение warning/protected, только на оценку.

На четырёх заранее выбранных DEV вычислить **side-by-side без адаптивных порогов**:

Zero candidate core или zero I-retained нельзя назвать PASS.
