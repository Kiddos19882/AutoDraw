**E0 — 2026-11-21, до написания и исполнения кандидата.** Remote HEAD baseline: `5b8638bda7298140a4aba0a59c32cd5ec48e4dd5`. Продолжаем неизменный ENGINE-001/BPRED S0→S6, строго внутри S4-R1; не возвращаемся к микропатчам S3, не подбираем очередные sigma/percentile ради долей процента. DEC-034/041/043/044/045 обязательны, как и неизменные quality gates и архивные FAIL.

## Почему и какой конкретный вопрос

AWEAK1 показал: помеченные человеком внутренние визуально цельные зоны не обязаны иметь один RGB; AWEAK2 Lab-edge warning повысил охват K лишь на +1.88 п.п. на 4 DEV, сложный `EZAL3k9ddfs.jpg` только +1.18 п.п., а на другом DEV утратил 19.07% I∩core. **AWEAK2 REJECT/NO_PROMOTION.** Пользователь просит не застревать на малых процентах и не заставлять его размечать точные пиксели. Следовательно, следующий тест проверяет **другую причину потерь**: P2 SLIC создаёт границы регионов даже внутри визуально близких Lab-цветовых поверхностей, а source-core запрещает полосы по всем таким границам. Можно ли убрать *лишь слабые искусственные SLIC границы* из гипотетического interior, сохранив защиту уже подтверждённых original source edges и сильного несогласия внутри региона? Никакого факта о реальном game128 owner не предполагается.

## Один фиксированный алгоритм AWEAK3, без sweep/ручной разметки в генераторе

1. Повторно загрузить **неизменные** исходные PNG/JPEG и четыре реальных A PNG+JSON из `75d0fb7e14d352a719691666cd6a55777dc4a713`, предварительно через существующий AQA1 `audit` (4 DEV originals, точно восемь файлов, все SHA). Обязательный E0 blob контроль AWEAK1 `a6ceeceb6095b2b23224ce8c412a44818302066c`, AWEAK2 `80a410cb5feb45dec3f7b36b0499e71120c8c512` и текущего AWEAK3. Хранить исходный RGB/alpha неизменными.
2. Использовать **те же** `generic_source_maps`, `original_source_region_uncertainty` и SLIC метки P2 (последние остаются UNKNOWN/не native). Получить соседние пары SLIC region ID на 4-соседнем исходном pixel-grid, только где оба пикселя opaque и ID отличаются. Для каждой пары вычислить **симметричную `deltaE_ciede2000` исходных P2 medoid RGB**. Порог **`DELTA_E_STRONG=12`** уже существует в P1/P2 source code; не изменять его и не называть реальной равностью owner. `weak adjacency`: `deltaE<12`; `strong adjacency`: `deltaE≥12`. На 4-соседних пересечениях ID разных регионов сформировать `strong_region_boundary` (на обеих сторонах) только для сильных пар. Для пары weak не добавлять SLIC-only border; **source original_edge, medoid disagree, original protected и alpha invalid** должны оставаться защищёнными.
3. Сформировать `retained_warning = original_source_edge | strong_region_boundary | existing_region_color_uncertain`, далее тот же P2 `ndimage.binary_dilation(iterations=1)`; `trial_core = opaque & ~original_protected & ~retained_warning_band & ~original_exact_white`. Сохранить необратимые source/owner/protection инварианты: `trial_core subset source_unknown`, `original core subset trial_core` (может только восстановить часть потенциального, ничего не снимает с established protected), `trial_core & original_source_edge==0`, alpha invariant, `source.owner=MISSING`, `stroke_admission=FORBIDDEN`. Даже `trial_core` **не** безопасен для реальной кисти, это лишь source-only hypothetical.
4. Человеческие A-маски **не участвуют** в расчёте region adjacency или trial_core, только оценивают после построения. Никакого нового RGB quantizer, ресэмплинга, графики по промптам, псевдо-референсов от моделей, дообучения и ручных поправок конкретным изображениям.

## Предварительно фиксированные показатели и критерий остановки

На **ровно тех же 4 DEV** сравнить old SLIC core против trial по общему core и I (человек отметил приблизительный visually same interior, не exact RGB), отдельно по I после erosion 2 source px. Параллельно считать **нежелательное пересечение K=critical|boundary с trial_core** и его изменение; а также K∩dilated(trial_core,2 source px), чтобы учитывать неточность ручных штрихов. Привести абсолютные значения, доли, знаменатели, per-source и pooled totals, количество unique weak/strong adjacency pairs, число возвращённых source core pixels, проверку protected-source неизменности и provenance. `K` — субъективный *weak proxy*, не истинный false-safe; `I` — субъективный визуальный interior, не true palette owner. Не сравнивать equality исходных RGB внутри I и не путать исходные pixel с logical game-px.

**Один кандидат, один E2 CI, один decision report.** Не перебирать deltaE threshold, sigma, SLIC compactness, erosion/radii после результата. Если выигрыш по пригодному I мал или увеличение K-in-core/near-core очевидно — **сохранить NEGATIVE и STOP**; даже при хорошем proxy-tradeoff не переносить в production, а переходить к отдельно согласованной native S4 validation/readiness по изначальному плану. Никаких «добить до 100%» и длительных DEV итераций. Незначительные улучшения **не являются поводом для нового цикла параметров**.

Output: один JSON artifact с исходными SHA, per-image/pooled diagnostics, известными hard limitations, исследовательскими E2 tests + CI report; отдельный компактный decision file и только необходимые актуальные docs. No H8, S0 BLIND120, reserved second50, exact game CHALK, E3/E4/E5, S5/S6, master, production, Stage6, Bridge or Monitor. Strict scientific SEMREF1/two-reviewer validation and original S4 **BLOCKED**; пользовательские приблизительные A достаточны для DEV exploratory, дополнительную разметку не запрашивать.
