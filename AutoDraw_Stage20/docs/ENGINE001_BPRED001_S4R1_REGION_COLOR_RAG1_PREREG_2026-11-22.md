## Вопрос и гипотеза

Гипотеза H-RAG1: если начальные SLIC-суперпиксели **только оригинального полного RGB/alpha** объединять через пространственный RAG с оценкой исходных границ и согласовывать выбор одной из 128 игровых красок **по региону**, можно сократить произвольные малые игровые цветовые островки относительно pixelwise nearest-Lab, сохранив узнаваемые исходные контуры и детали. Это **не** удаление готовых островков из FC1 PNG и не модификация старого output. Малые настоящие исходные детали сохранять; число областей само по себе — не показатель качества.

## Фиксированный объём RAG1

**Input:** произвольный raw оригинал с EXIF/alpha, исходный полный размер; версия, SHA256 и координаты сохраняются. Реальная engine128 палитра из pinned игрового JS `gameEngine/main.min_653f95bc.js` через проверенный `read_engine_palette()`. Старые E/F/G32/V44/P4D/FC1 художественные карты/маски/contours/outputs/plans **запрещены как вход, seed, target, repair и параметры**, как требует DEC-047. Допустимы лишь чистые source-only функции и исходная игровая палитра/native infrastructure.

**Один candidate:** existing `engine001_bpred_s4r1_generic_source_maps.original_source_region_uncertainty` даёт SLIC IDs по текущему оригиналу (первичные связные регионы; `REGION_TARGET_AREA=128`, `REGION_MAX_SEGMENTS=2048`, `compactness=6.0`, sigma0, masked opaque). Разорванные на компоненты одинаковые SLIC labels принудительно разделить по **4-связности**, независимо от ограничений версии scikit-image. Для каждого региона из текущего RGB — Lab mean/sufficient statistics, count, игровая nearest128 цена. Строить RAG только между реально соприкасающимися opaque 4-соседями; учитывать оригинальный Lab-контраст на общей границе. Изучаем **один** deterministic greedy merge по минимальному росту `E_color + E_boundary + E_fragmentation` при сохранении исходно контрастных/важных границ; назначить каждой финальной геометрической области один swatch из 128. `region_id` ≠ `color_index`: разные соседние исходные геометрические области могут получить один игровой цвет. Разделение плохо объединённых SLIC-областей рассматривается только когда подтверждён значимый исходный перепад и возможно без уничтожения деталей; не утверждать его реализацию, пока нет кода. **Не** применять жёсткое правило удаления всех островков до N клеток.

**Параметры пилота:** без image-specific ROI и tunable thresholds после просмотра; исходные SLIC-параметры неизменны. Для первого merge candidate: средняя Lab-дистанция между регионами не больше 12; при сильном исходном соседском контрасте (доля переходов c Lab-distance >12 свыше 25%) слияние запрещено; максимальный дополнительный вклад исходной palette squared-Lab RGB approximation при слиянии не больше `100` в суммарных source-pixel units (одна устранённая граница/регион). Если на выбранных изображениях candidate проигрывает по качеству, сохранять FAIL/NO_PROMOTION, не подбирать задним числом числа. `E_detail` на этом пилоте — отказ сливать пары по сильной исходной границе, а не притворная semantic segmentation. Детали с неизвестной семантикой — `UNKNOWN`.

**DEV — не открывать locked corpus:** ровно четыре уже известные оригинальные сцены: `testImages/wV6VeZI9S1Y.png` (KNOWN_CONTROL), `data/generated_autodraw_plan/images_31_first/Sanrio_Characters_Hello_Kitty_Image026.webp` (DEV), `data/generated_autodraw_plan/images_31_first/EZAL3k9ddfs.jpg` (DEV), `data/generated_autodraw_plan/images_31_first/images (1).png` (DEV). Файлы только **original raw**, SHA записать runtime до любой операции; проверить real bytes decode/mode/size. Не использовать восемь locked heldout, H8/BLIND120/second50 и вторую images2_50_second. Проверка независимости от prior masked/near-duplicate обязательна перед будущим heldout, но этот DEV запуск не объявлять blind.

**Сравнения и реестры:** на **одних и тех же source pixels** сопоставить original-nearest128 baseline vs region-coherent candidate: RGB/Lab MAE или RMSE, количество игровых цветов, цветовых 8-connected компонентов/одиночек/до3, количество region IDs, исходные сильные source-границы и сохранённый на них контраст игровых цветов, изменения near-source-original. Записать алгоритм/среду, raw hashes, JSON metrics и side-by-side PNG (original, pixel nearest128, regionIDs, RAG result и source edges). Исторические FC1/АWEAK3 — только отдельная интерпретация ПОСЛЕ нового отчёта, не вход и не параметр. Source-only E2 **не** равно реальному качеству игрового покрытия; полный artwork-тест возможен только independent original→новые region/color/contour→новый strokes→настоящий Egret с SHA и raw.

## Ранние критерии и stop rule

**E2 invariant PASS:** битовая сохранность исходного RGB/alpha, всё назначенное из 128 swatches, invalid/nonopaque не получать игрового owner, каждая region ID непрерывна по 4-связности, source original/old artistic data не подмешаны, два identical runs дают одинаковые IDs/color/metrics, synthetic separated-black/white/alpha test сохраняет явную границу. Время/размер/память сохранить в отчёте, не заявлять production performance.

**Исследовательское `PROMISING` только при:** не менее чем на 2 из 4 DEV примеров уменьшение количества singleton игровых компонент ≥15% относительно original-nearest128 без ухудшения source RGB MAE >15% **и** без потери явно сильной исходной контрастной границы в тесте; остальные результаты, даже неудачные, сохранять. Эти **новые prospective pilot metrics** не заменяют frozen quality/safety/coverage gates, не являются доказательством узнаваемости/semantics и не дают права production.

**Остановка:** ровно один RAG1 candidate, один DEV запуск и один итоговый отчёт. При существенном архитектурном FAIL — описать причину и следующий обоснованный шаг, а не series of lambda sweeps. Никакого автоматического продвижения в S4.4/S5, если интерфейс карт и качество не проверены. Формальный BPRED-S4 BLIND/native gate остаётся BLOCKED; S5/S6/E4/E5/CHALK NOT_RUN.
