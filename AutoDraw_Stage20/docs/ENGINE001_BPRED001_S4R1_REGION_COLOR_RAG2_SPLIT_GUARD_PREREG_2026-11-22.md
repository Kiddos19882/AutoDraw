## Гипотеза и принципиальное отличие от RAG1

RAG1 необратимо превращает каждый первоначальный SLIC-суперпиксель в один игровой цвет, **не разделяя** уже смешанные тонкие исходные детали. Гипотеза RAG2: если **до** регионального назначения создать дополнительные **4-связные компоненты внутри исходного SLIC по свежим, пересчитанным из оригинала пиксельным game128 предложениям**, а затем *только для ограниченно пригодных малых компонентов* оценить возможное присоединение через **реальное** 4-соседство, исходный локальный Lab-контраст и изменение ошибки цвета, сохранение исходных деталей будет существенно лучше RAG1 при уменьшении части искусственных цветовых островков. Это **новая исходно-ориентированная геометрия**, а не repair старого FC1, не pixelwise-baseline artwork как вход и не исторический исход RAG1 как seed.

## Один фиксированный исследовательский вариант

1. **Raw original:** EXIF-transposed полноразмерный оригинал RGB/alpha, immutable original sha; учитывать только `alpha=255` для owner, не выдумывать цвет в полупрозрачности. Game128 from pinned engine blob `46cc74de00b6cb5d207b1e1a2ffcd81613b6d388`. Reuse source-only SLIC (`REGION_TARGET_AREA=128`, `REGION_MAX_SEGMENTS=2048`, `compactness=6.0`, sigma0) и palette parsing без legacy art.
2. **Первичное разделение:** для исходных opaque пикселей *заново* вычислить nearest game128 в Lab (внутреннее пиксельное предложение для сохранения деталей, **не** финальный независимый owner алгоритм). Внутри каждого original-only SLIC label разбить геометрию по сочетанию `(SLIC ID, provisional palette index)` на 4-связные компоненты. Для любой компоненты цвет/площадь/mean source Lab/RGB, border neighbor count и origin-SLIC parent вычислить из **текущего RGB**. Не пересекать непрозрачную/прозрачную границу.
3. **Исходно-защищённый RAG:** для компонентов получить только **фактические** 4-соседства. Сосед допускается как кандидат на изменение регионального игрового цвета только если: размер исследуемой компоненты `<=3 source pixels` (отбор *кандидатов*, не приказ удалять их), исходный Lab-контраст **каждой** соединяющей её границы `<=12`, source-Lab расстояние между mean цветов компонент `<=12`, и пересчёт `RGB MAE` при перекраске текущего компонента в **реальный** соседний game128 swatch не ухудшает среднюю ошибку этих исходных пикселей более чем на `1.0 RGB channel unit`. Компоненты на исходных сильных границах и с высокой ошибкой перекраски остаются сохранёнными независимо от размера. Выбирать один best сосед с минимумом `added RGB MAE`, при равенстве max shared-boundary length / lower owner index. **Один синхронный проход**, без многократного рекурсивного порогового поиска, без настройки по изображению. Варьировать `1,3,12,1.0` после оценки запрещено в рамках RAG2.
4. **Выход:** game128 index и новые **4-связные геометрические component IDs** после guarded reassignment внутри исходных SLIC parents, отдельно source-strong-edge map (реальный RGB/Lab), preview и original SHA. `region ID != game index`. Итог не использовать для production/strokes/S4.4 до проверки. Итоговые region IDs могут оставаться раздельными при одинаковом swatch и иметь `UNKNOWN` semantic detail status.
5. **Строгая source independence:** как входы допустимы только original bytes / pinned game128 / универсальные stateless source helpers; RAG1/FC1/E/F/G32/V44/P4D художественные output, frozen human labels, уже полученные palette masks и strokes **запрещены**; RAG1 допускается только как независимый **после** результат отчёта и не в коде кандидата. Нельзя использовать RAG1 готовый region map ни прямо, ни как seed.
