# ENGINE-001 / BPRED-S4-R1 / RAG3 — prospective E0: иерархия основных поверхностей и защищённых деталей

**Дата:** 2026-11-22. **Статус:** E0 FROZEN BEFORE CODE; RAG3 IMPLEMENTATION/TESTS NOT_RUN. **Baseline HEAD:** `e8ceadf7fbb54c9bf56f9d140939ea32e4fcb106`; задача `S4.2+S4.3`, [DEC-048](DECISIONS.md#dec-048-s42s43-совместная-сегментация-связных-областей-и-выбор-игровых-цветов). **RAG1** [FAIL](ENGINE001_BPRED001_S4R1_REGION_COLOR_RAG1_E2_RESULTS_2026-11-22.md), **RAG2** [PARTIAL / NOT_PROMOTED](ENGINE001_BPRED001_S4R1_REGION_COLOR_RAG2_E2_RESULTS_2026-11-22.md); frozen originals, reports, E0, acceptance and failed CI unchanged.

## Гипотеза и границы

RAG1 ошибочно объединял важные исходные детали в один крупный swatch; RAG2 защищал их, но превращал каждую тонкую цветовую компоненту в самостоятельный геометрический region ID (до 79 787). **H-RAG3:** если разделить **связные основные поверхности** и **вложенные защищённые исходные детали**, можно сохранить узнаваемость и близость к original при существенно меньшей нагрузке region-ID/adjacency, чем RAG2. Это архитектурное разделение ответственности, **не** повторный sweep RAG2 area/Lab/RGB, не удаление всех островков меньше N и не repair FC1/RAG1/RAG2 PNG. Один фиксированный candidate, один DEV batch и один signed report.

**Input/provenance:** исходные байты полного original RGB/alpha с EXIF-transpose, SHA256, H×W; только opaque pixels получают owner. Пиннинг game128 из engine blob `46cc74de00b6cb5d207b1e1a2ffcd81613b6d388`. Только stateless source RGB/Lab/SLIC, palette и универсальные connectivity helpers, которые **заново** работают на текущем original. Запрещено читать E/F/G32/V44/P4D/FC1/RAG1/RAG2 derived art, masks, labels, strokes, preview или reports как input/seed/targets/parameter source. Исходный `nearest128` вычислять заново только для baseline, не использовать как самостоятельные **геометрические IDs**. Не открывать sealed H8/BLIND120/second50/images2_50_second.

## Один кандидат RAG3 (не менять после E0)

1. **Основные поверхности:** построить исходно-ориентированные SLIC superpixels на original, привести каждую метку к 4-connected компоненте, сформировать реальный spatial RAG по opaque 4-neighbors. Группировать **только соседние** superpixels по source Lab/RGB statistics и силе/протяжённости original boundary; не присваивать самостоятельный surface ID каждому pixel-nearest game128 island. Для воспроизводимости использовать неизменные source SLIC настройки `target_area=128, max_segments=2048, compactness=6.0, sigma=0`; алгоритм candidate применяет deterministic порядок обхода/ tie-break по исходным координатам и ID.
2. **Внутренние детали:** независимо от surface swatch вычислить **source RGB/Lab strong-edge evidence** на полном разрешении. Внутри каждого surface сохранять protected detail **mask/segments** по реально сильным исходным границам и внутренним контрастам, включая тонкие элементы, не требуя отдельного самостоятельного **surface** для каждой palette singleton. Защищённые detail-подрегионы хранить отдельным слоем `detail_id,parent_surface_id,source_edge,confidence/UNKNOWN`; не смешивать detail IDs с основными surface IDs. Там, где одна surface пересекает исходную сильную границу, **split main surface по подтверждённому непрерывному source edge**, а не стирать деталь или автоматически размножать main surface на каждый цветовой пиксель. Не утверждать semantic class без evidence.
3. **Региональный цвет:** каждому основному surface назначить game128 swatch по original RGB/Lab и соседям; protected detail-подрегионам разрешить отдельный game128 swatch **только при source-supported contrast** и хранить его как `detail_color` без превращения в main region. Сохранить отличие `surface_id` от `color_index` и `detail_id`. Любые повторные корректировки цвета допустимы **одним** детерминированным согласованием, без цикла tuning. Не ограничивать количество используемых цветов 32/53.
4. **Output contract:** `surface_id` (4-connected), `surface_color_index`, `detail_id`, `detail_parent_surface_id`, `detail_color_index`, `source_edge`, `unknown/alpha`, adjacency, coordinate/provenance/sha, и реконструированная game128 preview из этих **новых** слоёв. Surface connectivity проверять отдельно от detail connectivity; при неуверенности detail `UNKNOWN`, fail-closed для production. S4.4 contours ещё не объявлять готовыми, но source-edge/detail layer должен быть пригоден для их построения.
5. **Implementation constraint:** один исследовательский модуль в существующем S4 source-only runner с чистыми функциями; не создавать параллельный production planner, не изменять Stage6/executor/Bridge/Monitor/master. Если невозможно обеспечить детерминированное разделение поверхностей и деталей с этими условиями — зафиксировать `BLOCKED`, не подменять выход pixelwise labels.

## DEV и зафиксированные измерения

**Ровно четыре DEV/KNOWN_CONTROL originals:** `testImages/wV6VeZI9S1Y.png`, `data/generated_autodraw_plan/images_31_first/Sanrio_Characters_Hello_Kitty_Image026.webp`, `data/generated_autodraw_plan/images_31_first/EZAL3k9ddfs.jpg`, `data/generated_autodraw_plan/images_31_first/images (1).png`. Source original raw + original SHA в каждом manifest; один неизменный алгоритм/настройки для всех четырёх. RAG2 и RAG1 **только как опубликованные post-run baseline числа**, не художественные входы. Сохранить original, independent nearest128 baseline, main surface IDs, detail layer, reconstructed game128 map, original edges, atlas, counts, runtime и SHA всех raw.

**E2 invariants:** сохранение raw original и alpha; swatches строго game128; каждый surface_id 4-connected; parent detail существует и не пересекает alpha; 2 идентичных прогона дают одинаковые карты/manifest content hashes; synthetic: thin strong-contrast detail внутри uniform large surface **остаётся видимым** в reconstructed map; weak same-color noise не образует автоматически отдельный main surface; соседние разные surfaces могут иметь одинаковый game swatch; transparent never painted; unknown cannot be treated as production SAFE; provenance запрещает legacy art reads.

**Предварительные критерии (исследовательские, не frozen scientific S4):**
- на **≥2 из 4** DEV — reconstructed game128 source RGB MAE не хуже **115%** fresh nearest128 baseline, а количество одиночных игровых 8-connected компонентов меньше baseline на **≥15%**; эти показатели сохранены как сопоставимые с RAG1/RAG2 и сами по себе недостаточны;
- на **обоих сложных** DEV (`wV6VeZI9S1Y.png` и `EZAL3k9ddfs.jpg`) число **основных surface IDs** строго меньше **половины** подписанных RAG2 финальных геометрических IDs (то есть <5444 и <39894 соответственно), при этом synthetic strong thin detail must survive. Снижение счётчика main IDs не считается успехом, если detail layer фактически отсутствует, источник контуров потерян или визуально исчезли важные детали;
- фиксировать долю strong original edges, сохранивших локальный контраст reconstructed game128, площади details, нарушения границ, RGB MAE и source visual atlas **для всех четырёх**, включая отрицательные результаты. Не подгонять веса/пороги после результатов и не утверждать machine semantic truth без independent labels.

**PASS исследования** только если выполнены все перечисленные численные и synthetic gates, и визуальный обзор не выявил явного разрушения лиц/волос/контуров; иначе `FAIL/PARTIAL/NO_PROMOTION` с объяснением. Это не formal BPRED-S4 scientific acceptance и не обещание game native quality. Один candidate/один batch/один отчёт, максимум один отдельно обоснованный следующий архитектурный шаг, без threshold sweep.
