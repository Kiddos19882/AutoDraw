# ENGINE-001 / COLOR32-S2 — защита сильных границ при сокращении цветовых островков

**Пререгистрация:** 2026-11-17; исходная ветка `feature/image-geometry-optimization`; remote history baseline `084a726294e5622fa0aa207408121fbfe17671fe`. Уровень до запуска E0; отдельный эксперимент **до B3c**, без изменения production. Исторические COLOR32-S1 и PAL32-REGION-V1 сохраняются побайтово. Task owner: ENGINE-001 / V43-P4.

## Гипотеза и причина

Исходный PAL32 E объединяет 4-связные цветные островки площадью до 8 пикселей, если прирост CIEDE2000 не превышает 5.0 (максимум два прохода), но не учитывает исходные сильные границы при выборе замены. На E2 PILOT B→E число компонент сократилось 2369→1044, а posthoc E1 strong-source-edge overlap снизился с 86.1667 до 84.4167% (−1.75 процентного пункта). Гипотеза: защита изменения пикселей рядом с сильным исходным градиентом позволит вернуть не менее половины потери edge overlap при сохранении существенного выигрыша по количеству компонент.

## Контроль и единственная экспериментальная переменная

Источник (ф) `testImages/wV6VeZI9S1Y.png`, SHA256 `07cc4568cb5e90d9514bc6f6c2112fee623f87f8fd0cea02fa517b04108e502a`; ROI 150×240 LANCZOS. Палитра (ф) `data/palettes/browser_palette.json`, ровно 32 оригинальных игровых RGB, Git blob `461b5f3725b9b79888ad36e807b3cf4c9e445e98`; никаких синтетических цветов. B = `nearest32` по CIEDE2000; E = неизменный `tiny_region_merge` с `max_area=8, max_extra_delta_e00=5.0, iterations=2`. S2-G = тот же E, но каждый кандидат-пиксель с исходным градиентом не ниже 90-го перцентиля положительных значений защищён от изменения. Градиент = Sobel от `skimage.filters.sobel(color.rgb2gray(source/255.0))`; порог вычисляется на исходном ROI один раз до объединения. Никакой отдельной ручной маски глаз/лица и специальных координат: edge-gate является единственной независимой переменной. Это не сегментация отдельных семантических частей.

## Метрики и заранее фиксированный исход

1. Общая метрика `source-edge overlap`: процент пикселей top-decile Sobel исходного RGB/gray с границей между соседними *цветовыми индексами* (использовать `skimage.segmentation.find_boundaries(index_map, mode="outer")`). В отчёте дать B/E/G по одной методике. Пороговой ROI-маской служит исходный top-decile Sobel, не вывод каждого кандидата.
2. Количество 4-связных цветовых компонент по всем реально использованным меткам, число цветов (<=32), RGB MAE и средняя ΔE00 исходного RGB; объём изменённых пикселей к B, количество заблокированных компонентов, контроль целостности.
3. **Предварительный источник-only gate, а не native acceptance:** G должен восстановить >=0.875 процентного пункта от потери B→E в `source-edge overlap` (или минимум половину фактической потери при E2 пересчёте), сохранить сокращение 4-связных компонент против B не менее 25%; средняя ΔE00 G не хуже E+0.1. Если E2 показывает другие B/E значения, считать от **фактических** B/E и явно указать различие с E1 pilot. Статус `SOURCE_GATE_FAIL` при невыполнении любого условия; не перенастраивать порог после CI.
4. Защищённые edge-пиксели в G должны иметь те же индексы, что B, включая защищённые белые/тёмные пиксели; повтор запуска бит-в-бит одинаков.
5. Image review: важны два персонажа, глаза, лица, руки, светлые детали, волосы и одежда. Численный gate не доказывает узнаваемость: отдельный визуальный контроль. Не называть G победителем без native Egret.

## Реализация и проверка

Новый standalone (ф) `tests/run_engine001_color32_s2_edge_protection.py` повторно использует `nearest32`, `tiny_region_merge`, `read_source`, `read_palette`, `topology`, `quality` из PAL32-V1, не исправляет их задним числом. Edge-mask защищать без изменения frozen E: выполнять ту же детерминированную логику компонент, но отбрасывать кандидат целиком, если любой его пиксель в protected mask. Это намеренно консервативный тест. Test-файл проверяет фикстуру островка, edge preservation, детерминизм, provenance, негативный gate; CI отдельно создаёт PNG/maps/JSON, проверяет SHA и загружает всё как новый artifact с отдельным именем. **CI job success** означает корректное исполнение, не автоматическое прохождение source quality gate.

## Бюджет и безопасность

Source-only E2; никаких настоящих Egret мазков, игровых действий, CHALK, Stage6, Monitor, Bridge, `palette_quantization.py`, `palette_reduction.py` и изменения V44-B 410 финальных контуров. Не использовать synthetic vertices как CHALK. Для будущего полного fill сохраняются 99% per-color alpha24, 3 logical px internal/external leakage, <=3000 strokes / <=5900 synthetic vertices; рисовать круглой **настоящей** Egret кистью. E3/E4/E5 до последующего отдельного прогона: NOT_RUN. При отрицательном результате сохранять отчёт и PNG, не менять критерии ради PASS.

## Уточнение аудита метрик после E1 (2026-11-17; без изменения source gate)

Проверка оригинального (ф) `tests/run_engine001_color32_spatial_segmentation_s1.py` выявила важную **несопоставимость**: прежний S1 `top_decile_source_edge_overlap` = пересечение top-decile **градиентов исходного и преобразованного RGB**, полученных через OpenCV Sobel /8, с отдельным 90-м перцентилем для каждой картинки. Исходный S2 `edge_overlap_percent` = пересечение top-decile **градиента source** (skimage Sobel, только положительные значения для перцентиля) и `find_boundaries(indices, mode="outer")`. **Это разные определения и разные знаменатели**. Исторические B86.1667/E84.4167% не являются автоматическим baseline для S2 `source_gate`.

Для исключения ложных выводов в новый S2 report добавлено **отдельное** поле `historical_S1_RGB_gradient_overlap_percent`, дословно повторяющее градиентную формулу S1 через OpenCV. Изначальный S2 `edge_overlap_percent`, threshold 0.875pp/half of B→E и все другие пререгистрированные source gates **не изменены**. S2 source gate применяет только собственные **пересчитанные B/E/G по S2** показатели; исторические S1 значения показываются исключительно как дополнительная диагностика, не используются для управления gate. Сравнение S2 и S1 в отчёте разрешено только в колонке `historical_S1_RGB_gradient_overlap_percent` и с учётом различной версии квантования B и типа изображений. При отрицательном исходе источника/нетестированном Egret не объявлять пригодность заливки. Исправление реализовано отдельным коммитом `9c75f04265`; последующие проверки E2 необходимо привязывать к фактическому workflow SHA.
