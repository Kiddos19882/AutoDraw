## Fixed candidate variants / no post-result tuning
Source original RGB always grounds swatch color support and ROI evaluation. New P0 BILATERAL_LOW is merely an independent prefilter before quantization. CIELAB and CIEDE2000 via skimage original, fixed actual palette.
- **G32_FROZEN**: original archived G32 RGB (reference).
- **P0_NEAREST32**: independent nearest palette per P0 BILATERAL_LOW RGB, CIEDE2000, row-major tie to lowest palette index, no spatial regularizer.
- **B1_CHROMA12**: select smallest original-source CIEDE2000 among actual 32 swatches satisfying: palette Lab chroma <= original pixel Lab chroma +12, palette L* <= source L* +22. If no valid candidate, pick lowest-∆E among chroma-safe, report fallback; if none, black31 and log. Same tie to low palette index.
- **B1_CHROMA20**: identical but +20 chroma threshold (an independently fixed sensitivity, not a re-tune).
- **B1_CHROMA12_SPATIAL**: initial CHROMA12 labels, then 2 synchronous deterministic 4-neighbor Potts minimization iterations; total per-label unary source CIEDE2000, invalid candidates prohibited; extra cost 2.5 per unlike neighbor if (a) BOTH pixels are outside original protected union and (b) original-source neighboring ΔE00<=8. Protected pixels retain initial valid swatch label bitwise; no smoothing across protected seam. No separate hue ban, no semantic inference, no forced background painting. Nearest tie by palette index.

Protected source geometry is **not** promised the original RGB after game32 conversion; the guarantee is that spatial cleanup cannot alter the constrained labels on protected pixels. This avoids falsely claiming exact RGB protected after palette mapping.

## Frozen metrics and acceptance
Compare all output maps against ORIGINAL_RGB from pinned P0, and G32 baseline using same methods: mean / p95 CIEDE2000 full image and six historical M0 named detail ROIs; per-pixel CIELAB chroma-excess >12 vs original, diagnostic #A5015B/#E20085 swatch counts and suspect components; foreground nonwhite 4-connected components/singletons, exact palette membership, source strong-edge overlap using fixed original grayscale Sobel90 threshold (mapped RGB Sobel at same threshold), protected bitwise label equality to CHROMA12 for SPATIAL variant, no off-palette colors. Compare candidate vs source G32 in identical ROI and baseline. Report changed/swatches/component counts and raw maps; no estimate of exact CHALK or brush coverage.

**Strict first game32 source screen (all requirements):** mean ΔE00 <= frozen G32 mean +1.0, p95 <= frozen G32 p95+1.0; chroma-excess suspect count <=40% of G32 (note original frozen A1 count 1368); original source fixed-edge overlap >= frozen G32 overlap-0.02; nonwhite components and singletons each <= frozen G32; per-face eye and hands ROIs mean ΔE00 may not worsen by >2.0 vs G32. All checks must be evaluated on the complete 150×240 ROI, no threshold editing after measurement. This is not image recognition quality or user acceptance. If fails mark SOURCE_GATE_FAIL and retain negative image; if passes mark SOURCE_SCREEN_PASS_VISUAL_PENDING only. In addition, export "RGB unrestricted P0" separate from game32 to keep visibility of the loss.

**Expected risk:** true #500047 purple/brown shadows may map to near-black due to chroma caps; significant face detail may be erased because 32 swatches are sparse. Strong edges, off-white background and tiny details may be hard to preserve even with V44 contour; the experiment may fail. User visual assessment of character identity remains decisive, particularly faces, hands, clothing. A good source metric alone does not prove good gameplay.
