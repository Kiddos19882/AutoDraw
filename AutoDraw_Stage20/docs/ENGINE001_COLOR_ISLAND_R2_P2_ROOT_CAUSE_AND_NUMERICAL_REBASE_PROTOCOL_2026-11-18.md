### Root cause A — фон: scope не эквивалентен, ошибку нельзя «исправить» просто побелив

Независимо пересчитано **по замороженной M0 raw RGB/B0/background PNG**: 
- P1 original-first border-connected white10 background: **21 376** пикселей; frozen B0 game32 white index30: **25 305** пикселей.
- Все **3929** несовпадений — `B0_white ∧ original_source_foreground`. Обратных (`source_BG ∧ B0_nonwhite`) **0**. Среди 3929 только 1326 original пикселей с RGB каждого канала≥245; остальные 2603 не trivially pure-white. Маска несоответствий включает **572 4-connected компоненты**, крупнейшие площади 1157, 367, 316, 268, 159 px. Исходник на этих пикселях может содержать off-white/антиалиасинг/реальную белую часть одежды; B0 nearest game swatch не равен semantic background truth.
- **Вывод:** нельзя принудительно сделать source-BG = G32 white, нельзя перекрасить истинную белую деталь как фон. В RGB partition foreground/background и game32 white owner учитывать **раздельно**. Для P2-P1 сохранить frozen white10 source prior и диагностировать отдельно original-source BG, B0 swatch white, исходный nearwhite proxy; смена BG threshold — только отдельный P2-P2 prereg с source/edge guard.

### Root cause B — P1 gradient-overlap gate зависит от перекалибровки порога, а не только от физически потерянного края

Независимо пересчитано через `skimage.filters.sobel(color.rgb2gray(source/255.))` и 90-й перцентиль положительных градиентов **из замороженных M0 PNG**:
- `source` threshold = **0.2935634334269342**; `M0_NO_MERGE_RGB` threshold = **0.2449592784872437**; `M0_MERGED_RGB` threshold = **0.2467878935447204**.
- P1 «потерянные» шесть original-strong-edge совпадений в координатах (y,x) `(34,72),(62,71),(94,29),(118,41),(121,85),(189,82)` имеют **совершенно одинаковый градиент до и после**, между 0.24551 и0.24662; изменился лишь пересчитанный threshold. Пересечения при динамическом пороге **1641→1635**. Если для обеих M0-карт применить единственный порог исходного RGB `0.2935634334269342`, совпадения **1394→1394**.
- **Вывод:** P1 FAIL зафиксирован правильно по исходной методике, но он не доказывает потерю этих шести реальных локальных краёв. В P2-P1 новый метод сравнивает одну и ту же шкалу исходного RGB, сохраняет историческую динамическую метрику **только как отдельно обозначенную диагностику**; не переобъявлять P1 PASS.

### Root cause C — медоид в парных микрорегионах не имеет устойчивого tie-break

- P1 `M0_original_region_ids.tiff` и `M0_merged_region_ids.tiff` **побайтово равны** при повторном GH CI-run повтор [CI44210206955](https://github.com/Kiddos19882/AutoDraw/actions/runs/44210206955), source code SHA `62fdc38e`, дает идентичные архивные RGB/label PNG относительно M0 `bf2ffce` при сопоставимом CI окружении.
- При независимой обработке той же замороженной original RGB+label карты численная реализация выбора CIELAB medoid в **37** очень малых регионах даёт альтернативный **исходный** RGB-пиксель; отличаются **78 displayed pixels** (230 RGB channels). Проверены все affected regions: archived original color и повторный `argmin` эквивалентны по квадрату Lab расстояния до source median в пределах **4.55×10⁻¹³**; это numerical tie, а не mismatch исходного RGB или изменение целевой области.
- **Вывод:** независимое сравнение цвета N1 с published frozen M0 нельзя делать без стабильного правила медоидного tie-break. Это не оправдание для проигнорированного `frozen_m0_rgb_render_exact=False` в N1/N2 отчётах: P1 остаётся FAIL. P2-P1 должен детерминированно выбрать один исходный RGB member среди численно равных кандидатов **до** первого нового кандидата и проверить cross-run bitwise equality.

## 2. P2-P1 — зафиксированные изменения численной *методики*, НЕ изменение P1

1. **Исходные данные:** source original SHA, palette blob и B0 SHA неизменны. Logical H240 W150, 36000 pix, 4-connectivity для label owners. **M1 original RGB segmentation намеренно равен P1**: fine SLIC `n_segments=1600,compactness=5.0,sigma=0.3` и coarse contextual SLIC `n_segments=320,compactness=8.0,sigma=0.7`, `start_label=0,convert2lab=True,enforce_connectivity=True`; foreground from original-LAB-white ΔE00<=10, 8-connected border component, no B0 seeding. 2. **Стабильный medoid:** для каждого неизменного/объединённого региона выбирается только его original RGB member. Для каждого member CIELAB вычислить square Euclidean distance к **Lab median** региона (как ранее), выбрать множество кандидатов с `distance_squared <= minimum + 1e-9`, затем **минимальный row-major original source pixel index**. Этот численный epsilon — исключительно новая P2-P1 tie-policy; seed source/palette pinned. Freeze specific numpy/scikit-image/Pillow/opencv/scipy versions at first CI M1, record versions+environment, verify same medoids on two independently constructed arrays of identical bytes (PNG-decoded and original-resized) and 2-member exact-tie fixtures.

4. **Метрический контроль:** compute once `source_sobel90_threshold` from exact original RGB. Separately report the historical P1 candidate-specific percentile overlap with explicit `NOT_EQUIVALENT_TO_FIXED_THRESHOLD` label, do not mix gates. No post-run threshold adjustment.
5. **Фон:** do not adopt B0 white as semantic background. Produce independent maps `source_white10_border_connected`, `frozen_G32_white`, `source_nearwhite_all_rgb245` and 4-connected mismatch owners; source RGB outside source BG still keeps source-derived colors. No BiRefNet or DINO mask in M1 baseline. A future independently registered P2-P2 may test source-white thresholds, but **not** in P2-P1.
