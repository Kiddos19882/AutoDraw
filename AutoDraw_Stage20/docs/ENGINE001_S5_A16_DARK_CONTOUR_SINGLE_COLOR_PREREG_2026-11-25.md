# ENGINE-001 / S5 A16 — Illustration dominant dark contour: route/brush ablation (E0, 2026-11-25)

**Frozen baseline:** branch `feature/image-geometry-optimization` HEAD before experiment `70b13039e4518ce5a4eec57914667e146ee2f898`; A15.1 R2/T10 accepted by user. Original Illustration source from `run_engine001_s5_native_transfer_p2.CASE["illustration"]`, Git blob `27050fbd1661f1c36a0abea3ee0dc25eb84d86a5`. Immutable source RTV04 preparation and F4 NoDot-L5 band contour are retrieved from archival A14 NoDot and L5 workflow artifacts, checked against their pinned SHA and artifact reports; the A15.1 artifact is a historical reference, **not** input for choosing candidates. Source color mask is sliced from the **same archived RTV04 source contour radius2**; no replacement segmentation.

**Question:** which isolated one-color route/brush treatment reduces stroke count and/or source path length while keeping the recognizable dark contour in actual Egret native PNG? No all-zone fill and no multi-color painting in this experiment.

**Selection, fixed before results:** construct radius2 contour band on archived RTV04 `rtv-prepared.png`. For each non-white RGB color in that band compute sRGB Rec.709 luminance `(2126R+7152G+722B)/10000`; among colors with luminance <= 128 choose the one with **most pixels**, tie by lower luminance then ascending RGB. If none meet threshold: fail closed. Record HEX, total source pixels, and full dark-color ranked table. This is the most frequent dark contour color, not automatically the numerically darkest swatch.

**Controls/treatments:** frozen A15.1 stage1 F4-L5 contour paths **filtered strictly by chosen exact color** (control); existing A14 source-route generators `b/cfree/d/e/f` (horizontal/connected/shell, etc.) and A14 free-angle `f1/f2/f3/f4/f6` on the same one-color band. Three direct width1/2/3 comparisons for selected `cfree` horizontal long-lane route. Mixed 3→2→1 and 2→1 are evaluated only as explicitly separate routing layers (do not count as preserving equal coverage if it differs). All native paths are real Egret 5.4.1 `BoardPane/WebGLRenderer`, normal, smoothing off, unlimited strokes; no cap 128 vertices, no dots, **strict source arc length >5 pixels** for all treatments. Source-mask path proposal has no authority as a footprint estimate; actual pixel coverage/leakage is decided by Egret readback.

**Measured per treatment:** plan stroke count, count by width, vertices, total/mean/min/max source arc length (px), sum/mean logical Egret length (px), max stroke vertices, native alpha24/128 within target/outside target/outside board, foreground coverage, simulation paint counter, PNG/plan SHA256. Report *both* source and native pixel spaces, never call simulator counter exact game CHALK. Native per-scene 10% outside support is **diagnostic**, not a retroactive replacement for A15.1 per-stroke 10% gate; only treatment meeting comparable quality can be candidate. Preserve all failures and rejected variants.

**Native validity:** same original and RTV04 target SHA; F4-L5 archived plan/source SHA and geometry; blank Egret, runtime fixture guard removal verified against unchanged reference frame; physical 1..10 native brush footprints; plan/source owner and color assertions; full raw/native PNG and JSON + immutable zipped workflow artifacts. No human visual PASS, E4 game runtime, exact CHALK, E5 or production promotion from this test.

**Execution:** existing Windows native Selenium/Egret test harness with GitHub Actions workflow `engine001-s5-native-a16.yml`; source-only contracts first, then native job. Outcomes `PASS/FAIL/PARTIAL/NOT_RUN` only after actual jobs and collected evidence. If experiment cost is high, retain partial evidence rather than claim success.
