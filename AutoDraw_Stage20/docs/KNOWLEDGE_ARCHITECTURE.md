# Архитектура знаний и документации AutoDraw

**Статус:** ACTIVE — постоянная схема управления знаниями  
**Назначение:** определить роли документов, источники истины, навигацию, обновление и хранение истории.

## 0. Быстрое восстановление контекста (2026-11-08)

Краткая актуальная цепочка: [PROJECT_STATUS](PROJECT_STATUS.md) → [TASKS](TASKS.md) → [ROADMAP](ROADMAP.md), затем профильные [DECISIONS](DECISIONS.md), [TEST_RESULTS](TEST_RESULTS.md) и подтверждающие исходники/CI. Полные состояния до реорганизации сохранены как `*_HISTORY_THROUGH_2026-11-08.md` **в той же папке** ради рабочих относительных ссылок. Архивы не становятся ещё одним текущим статусом. [Полный индекс](README.md).

## 1. Слои знаний

1. Реализация: исходники, конфигурации, схемы, тесты и исполняемые сценарии.
2. Управление: статус, задачи, roadmap, решения и журналы.
3. Справочники: архитектура, API, модели данных, интерфейсы, зависимости и запуск.
4. Доказательства: протоколы, первичные данные, анализаторы, CI и отчёты.
5. История: прежние планы, снимки состояния, устаревшие дизайны и отменённые инициативы.

Слои связываются ссылками, но не копируют друг друга целиком.

## 2. Источники истины по назначению

| Объект | Канонический источник |
|---|---|
| Фактическое поведение | Исходники текущей ветки и runtime evidence |
| Контракт/формат | Схема, модель или код-валидатор |
| Покрытие тестами | Тестовые файлы |
| Факт прохождения проверки | Конкретный CI run/job или локальный результат |
| Текущее состояние | PROJECT_STATUS.md |
| Задачи и критерии | TASKS.md |
| Порядок работ | ROADMAP.md |
| Принятые решения | DECISIONS.md |
| Хронология | WORK_LOG.md |
| Значимые изменения | CHANGELOG.md |
| Навигация | docs/README.md |
| Результат исследования | Первичные данные и официальный анализ/отчёт |
| Историческое состояние | Датированный документ и соответствующие коммиты |

Ни один справочник не заменяет исходник. Тест не доказывает непокрытые сценарии. Исторический документ не устанавливает текущий статус.

## 4. Один владелец изменяемого факта

Каждый изменяемый факт имеет одно место, где он поддерживается актуальным. В других документах допустимы резюме и ссылка, но не независимая копия статуса.

Например: статус задачи — TASKS; состояние инициативы — PROJECT_STATUS; порядок — ROADMAP; решение — DECISIONS; метрики опыта — первичный отчёт/данные. Если факт нужен в нескольких местах, явно определить владельца и синхронизировать ссылки.

## 5. Жизненный цикл документа

Для новых содержательных документов и при существенном пересмотре указывать статус, назначение, область действия, дату/версию проверки (если важна), канонический источник и связи.

- ACTIVE — актуален и используется.
- DRAFT — проект, не обязательное правило.
- COMPLETED — процедура/работа завершена; результаты действуют в заявленной области.
- HISTORICAL — достоверный снимок прошлого.
- SUPERSEDED — заменён более новым документом, сохраняется.
- ARCHIVED — не используется в текущей работе, но сохранён.

Статус документа не равен уровню доказательности и не означает универсальность результата.

## 6. Разрешение противоречий

Разбирать конфликт по предмету:
1. Реализация: текущий код и runtime evidence описывают фактическое поведение.
2. Тесты: показывают покрываемые случаи; результат запуска — факт прохождения.
3. Намерение: принятое решение определяет допустимое направление, но не подменяет описание фактического поведения.
4. Текущий статус: свежий проверенный статус выше старого roadmap/снимка.
5. Эксперимент: первичные данные и воспроизводимый анализ выше пересказа; вывод ограничен протоколом.
6. История: коммиты и датированные документы объясняют прошлое, но не задают текущий статус.

Не исправлять конфликт молча. Зафиксировать расхождение, обновить актуальный слой и сохранить исторический контекст.

## 7. Навигация

- docs/README.md — единственная главная карта Markdown-документации.
- Общие документы размещать в AutoDraw_Stage20/docs/, если им не требуется соседство с компонентом.
- Группировать ссылки по управлению, архитектуре/API, эксплуатации, экспериментам, результатам и истории.
- Не создавать дублирующие индексы без самостоятельной необходимости.
- Связывать технические файлы, тесты и workflow с соответствующими документами.

## 8. Создание, обновление, объединение и удаление

Перед созданием найти аналоги, определить владельца факта, выбрать существующий тип документа и обосновать самостоятельность новой темы.

При обновлении менять только затронутые сведения, сохранять первичные ссылки, не переписывать историю и явно указывать замену старого документа.

Перед объединением/удалением проверить входящие ссылки, уникальные сведения, первичные данные и доказательства. Сохранить полезную историю либо перенести её с явной ссылкой. Устаревший статус сам по себе не является основанием для удаления.

## 9. Матрица синхронизации

| Событие | Документы |
|---|---|
| Новая/закрытая задача | TASKS; PROJECT_STATUS/ROADMAP при влиянии; WORK_LOG |
| Постоянное решение | DECISIONS; затронутые справочники/планы; WORK_LOG |

| Архивация/замена документа | docs/README.md и входящие ссылки |
| Изменение пользовательского поведения | CHANGELOG и эксплуатационная документация |

## 10. Ссылки и доказательная прослеживаемость

Использовать относительные ссылки внутри репозитория; проверять регистр и существование целей. Для воспроизводимых утверждений указывать commit SHA, CI run ID и artifact ID. После перемещения/удаления проверять входящие ссылки в заявленном объёме.

## 11. Шаблон документа

```markdown
# Название

**Статус:** ACTIVE / DRAFT / COMPLETED / HISTORICAL / SUPERSEDED / ARCHIVED
**Назначение:** ...
**Область действия:** ...
**Проверено:** YYYY-MM-DD (если применимо)
**Канонический источник/связи:** ...
```

Исторический отчёт дополнительно фиксирует дату, версию/commit, среду, входные данные и ограничения.

## 12. Что не создавать без необходимости

Не создавать второй README/roadmap, дублирующий текущий статус, сводный файл-копию всех экспериментов, краткие документы-пересказы или динамический список ограничений, который повторяет PROJECT_STATUS и специализированные отчёты.

Система должна уменьшать число конкурирующих источников, а не увеличивать его.
