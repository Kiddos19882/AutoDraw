# План документирования и ведения AutoDraw

План описывает только документирование структуры проекта и организацию работ. Он не является планом анализа или изменения поведения программы.

## Статус аналитических планов

Аналитический план этапов 7–10 отменён пользователем 31 октября 2026 г. Эти этапы не переносятся в настоящий roadmap и не должны возобновляться автоматически. См. [архивный план](../PROJECT_ANALYSIS_PLAN_10_STAGES.md).

## Фаза 1. Базовая документация

- [x] Создать единый индекс документации.
- [x] Описать верхнеуровневую архитектуру.
- [x] Составить первичный каталог исходных компонентов и тестов.
- [x] Описать основные каталоги данных и переменные окружения.
- [x] Описать локальный запуск, тестовые команды и Windows-сборку.
- [x] Создать файлы управления проектом.

## Фаза 2. Справочник исходников

- [ ] Создать справочник общих геометрических моделей.
- [ ] Документировать модели DrawingPlan, Stroke и Point.
- [ ] Составить каталог модулей preparation с назначением и публичными интерфейсами.
- [ ] Составить каталог модулей executor с назначением и публичными интерфейсами.
- [ ] Документировать интеграционные интерфейсы между preparation и executor.
- [ ] Документировать интерфейс Game Monitor как отдельного вспомогательного инструмента.
- [ ] Составить карту импортов и точек входа.

## Фаза 3. Справочник форматов и хранилищ

- [ ] Документировать формат проекта `.autodraw`.
- [ ] Документировать JSON DrawingPlan и цветные планы.
- [ ] Документировать форматы профилей палитры и калибровок.
- [ ] Составить реестр результатов и экспериментальных manifest-файлов.
- [ ] Указать версии схем, обязательные поля и расположение файлов там, где это подтверждено кодом.

## Фаза 4. Завершение комплекта

- [ ] Проверить относительные ссылки и наличие путей.
- [ ] Сверить все перечисленные интерфейсы с текущими исходниками.
- [ ] Обновить индекс документации.
- [ ] Проверить, что Git diff содержит только разрешённые Markdown-файлы.
- [ ] Зафиксировать итоговый HEAD и commit в WORK_LOG.

## Фаза 5. Сопровождение

При последующих изменениях:
1. определить затронутые документы;
2. обновить описание интерфейса/формата вместе с изменением;
3. добавить запись в WORK_LOG;
4. добавить запись в CHANGELOG для значимых изменений;
5. обновить задачу в TASKS;
6. проверить ссылки и пути.

## Границы

Не входят в этот план: анализ алгоритмов, аудит поведения, производительности, качества, безопасности, браузерные и игровые эксперименты, рефакторинг и исправление кода.
