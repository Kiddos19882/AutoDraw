# План ведения и документирования AutoDraw

План описывает работы по организации документации и управления проектом. Он не является планом изменения алгоритмов или поведения программы.

## Фаза 1. Базовая документация

- [x] Создать единый индекс документации.
- [x] Описать верхнеуровневую архитектуру.
- [x] Составить каталог исходных компонентов и тестов.
- [x] Описать конфигурацию, пользовательские данные и переменные окружения.
- [x] Описать локальный запуск, тестовые команды и Windows-сборку.

## Фаза 2. Управление проектом

- [x] Создать реестр задач.
- [x] Создать журнал проектных решений.
- [x] Создать журнал выполненных работ.
- [x] Создать журнал значимых изменений.
- [ ] Согласовать единый формат статусов и идентификаторов задач для будущих работ.
- [ ] Внести в реестр все активные задачи из действующих планов без дублирования исторических записей.

## Фаза 3. Проверка документации

- [ ] Проверить относительные ссылки всех новых Markdown-файлов.
- [ ] Сверить все перечисленные пути с текущим Git tree.
- [ ] Сверить описания точек входа и команд с текущими batch/Python/YAML-файлами.
- [ ] Сверить все настройки и переменные окружения с текущим исходником.
- [ ] Обновить корневой README Stage20 ссылками на новый каталог документации.
- [ ] Убедиться, что Git diff содержит только Markdown-файлы.
- [ ] Зафиксировать итоговый HEAD и commit.

## Фаза 4. Регулярное сопровождение

Для каждого будущего изменения:
1. Определить затронутые документы.
2. Обновить их в одном рабочем цикле с соответствующей задачей.
3. Добавить запись в WORK_LOG.
4. Добавить запись в CHANGELOG, если изменение значимое для пользователя или разработчика.
5. Обновить статус задачи в TASKS.
6. Проверить относительные ссылки и актуальность путей.
7. Не отмечать задачу завершённой до проверки результата.

## Вне текущего плана

- Анализ алгоритмов и поведения программы.
- Аудит производительности и корректности.
- Рефакторинг и исправление кода.
- Изменение тестов и CI.
- Браузерные и игровые эксперименты.

Эти виды работ требуют самостоятельных задач и отдельного разрешения.
