# AutoDraw — этап 14: управление исполнением и диагностика

Этап 14 укрепляет исполнитель Stage 6, не меняя формат `DrawingPlan JSON`, геометрию штрихов и рабочие значения калибровки.

## Что изменено

- **Остановка во время задержек.** Обратный отсчёт, паузы перед/после нажатия, интервалы движения и удержание конца штриха теперь ожидают через `Event.wait()`. Запрос остановки прерывает ожидание сразу, а не ждёт окончания таймера.
- **Различение причины остановки.** В отчёте различаются кнопка остановки, F12, аварийный failsafe PyAutoGUI и ошибка исполнителя.
- **Очистка мыши.** Команда `mouseUp()` вызывается после каждого штриха и ещё раз в финальном `finally`. Ошибки команды записываются; неудачная финальная очистка переводит запуск в `failed`.
- **Повторная проверка области.** Перед каждым запуском X/Y/ширина/высота сверяются с текущим размером экрана. Это ловит устаревший профиль после смены разрешения или монитора.
- **Строгие диапазоны.** Параметры ExecutorConfig валидируются по тем же диапазонам, что и элементы интерфейса: шаг 0.5–20 px; задержка точки 0–100 мс; остальные паузы 0–500 мс; обратный отсчёт 1–30 с.
- **Понятное состояние.** Интерфейс показывает подготовку, обратный отсчёт, рисование, остановку, завершение и ошибку.
- **Отчёт для каждого итогового состояния.** JSON пишется атомарно в `results/`, получает уникальное имя и включает причину остановки, ошибки очистки, конфигурацию, экранную область, преобразование плана, версию Python/систему и SHA-256-отпечатки исходного и исполняемого плана. Отчёт создаётся и для исключений до возврата сводки исполнителя.
- **F12 и PyAutoGUI FAILSAFE остаются включены.** FAILSAFE по-прежнему не отключается.

- **Продление линий на 2 px.** По умолчанию исполнитель добавляет 2 px к конечной точке каждого открытого штриха, двигаясь вдоль последнего сегмента. Координаты плана не переписываются; замкнутые контуры и начальные точки не меняются. Настройка 0–20 px, продление ограничивается границами холста.

## Важные уточнения

- Успешный `mouseUp()` означает, что вызов PyAutoGUI завершился без исключения. Программа не может независимо подтвердить, как браузер или физическая среда обработали событие; если команда отпускания завершилась ошибкой, интерфейс явно просит проверить состояние мыши вручную.
- После остановки программа **не продолжает рисунок автоматически**. Она не умеет надёжно узнать, какие штрихи доска фактически приняла и что частично осталось на холсте. Автоматическое продолжение без такой проверки могло бы дублировать штрихи.
- В Stage 6 уже были прогресс, F12, кнопка остановки и `mouseUp()` в `finally`; они сохранены и усилены, а не реализованы второй раз.
- Формат DrawingPlan и координаты плана не менялись. Начальные значения калибровки сохранены: 2 px, 10 мс, паузы 20/20/40 мс, удержание 50 мс и отсчёт 5 секунд.

## Запуск на Windows 10/11

Запустите `run_stage14.bat`. Чтобы установить зависимости вручную из CMD в папке проекта:

```bat
py -3 -m pip install -r requirements.txt
py -3 stage6_execute_plan.py
```

Пакет основан на полном исходном проекте Stage 6. Файлы этапов 1–5 оставлены в архиве как исходные инструменты; основной обновлённый исполнитель — `stage6_execute_plan.py`.

## Тесты

Запустите `run_tests.bat` либо из корневой папки:

```bat
py -3 -m unittest discover -s tests -v
```

Новые тесты моделируют успешный запуск, F12, остановку в обратном отсчёте и во время штриха, failsafe, исключение при перемещении, неудачную команду `mouseUp()`, диапазоны конфигурации и сохранение отчётов. Управление реальной мышью в тестах не выполняется.


## Адаптивные кисти Stage 19/20

1. На Stage 19 постройте цветной план, рассчитайте рекомендации и экспортируйте **отдельный** файл адаптивного плана кистей.
2. На Stage 20 откройте сначала исходный цветной scanline-план, затем соответствующий адаптивный файл. Stage 20 сверяет SHA-256, поэтому файл кистей от другого изображения не будет принят.
3. Откройте в игре расширенный режим рисования с ползунком размера кисти. Заполните экранные координаты положения бегунка для значений 1 и 30, координату Y и его текущее значение перед запуском. Подтвердите калибровку на текущем разрешении.
4. Перед запуском вручную выставьте бегунок на указанное текущее значение. При изменении координат или начального значения подтверждение сбрасывается.
5. При исполнении AutoDraw перетаскивает бегунок только при изменении рекомендуемого размера. Координаты ползунка должны находиться за пределами выделенного холста. Если экранное разрешение отличается от калибровки либо координаты попадают внутрь холста, запуск блокируется.

Адаптивные штрихи используют `line_extension_px_override=0`, чтобы исполнитель не продлевал линию за геометрически проверенную область. Обычные одноцветные и обычные цветные планы сохраняют стандартное продление 2 px. Переключение кистей проверено тестовыми двойниками PyAutoGUI, но точность фактического значения ползунка нужно отдельно подтвердить на реальной игре, прежде чем запускать большой рисунок.
