# Game Monitor 0.1.2

Диагностический DevTools-наблюдатель для браузерной игры AutoDraw. Он не отправляет игровые команды и не управляет мышью, но временно оборачивает методы экземпляра BoardPane; поэтому называть его полностью пассивным или неинвазивным до проверки overhead и восстановления методов нельзя.

## Источник сведений об игре

Клиентский bundle (только чтение, ветка `master`):

`AutoDraw_Stage20/fileGameEngine/main.min_570122a1.js`

SHA-256: `df5a411e91010cd59f010a78a460baf3bd6d2af36816cb2e73c9de5070762b3d`.

Монитор ориентируется на исследованные методы `BoardPane`: `onDrawStart`, `onDrawing`, `onDrawingEnd`, `setRadius`, `updateLess`, а также на `atom.points`. BoardPane имеет логический размер 460×240. Клиентский код сам добавляет точки и перерисовывает доску во время активного штриха; сервер не участвует непосредственно в обработке движения и перерисовке. Последующее сохранение/синхронизация — отдельный процесс.

## Подключение

1. Откройте игру в Chrome или Edge и дождитесь появления доски.
2. Нажмите F12 → Console.
3. Откройте файл `game_monitor.js` в репозитории, скопируйте весь текст и вставьте в Console.
4. Разрешите вставку кода в DevTools, если браузер попросит (не включайте это разрешение для неизвестного кода).
5. После вставки проверьте ответ и выполните:

```js
AutoDrawGameMonitor.status()
```

В версии 0.1.2 статус содержит `frameContext`. Для правильного запуска `isTopFrame` должен быть `false`, а `currentFrame` должен указывать на `eufbpet.hust.me`. Если `isTopFrame: true`, выбран верхний документ и поиск доски там не сработает. Если после запуска внутри iframe `boardDetected` всё ещё `false`, сохраните JSON — тогда будем исследовать структуру уже правильного контекста. Автопоиск использует `window.egret.MainContext.instance.stage` и обходит display list.

## Управление

```js
AutoDrawGameMonitor.status()       // текущее состояние
AutoDrawGameMonitor.export()       // получить объект с телеметрией
AutoDrawGameMonitor.download()     // скачать JSON
AutoDrawGameMonitor.clear()        // очистить буфер событий
AutoDrawGameMonitor.stop()         // остановить и восстановить методы BoardPane
AutoDrawGameMonitor.start()        // снова запустить наблюдение
```

Для ручного подключения, если BoardPane найден в DevTools вручную:

```js
AutoDrawGameMonitor.attach(boardPaneInstance)
```

## Что фиксируется

- обнаружение/отключение BoardPane;
- начало и завершение штриха;
- изменение радиуса через `setRadius`;
- изменения числа сохранённых координат во время `onDrawing`;
- вызовы `updateLess`;
- снимки счётчика точек и последней координаты; `atom.points` разбирается по структуре движка: массивы штрихов содержат объекты `egret.Point` с числовыми `x` и `y`;
- Resource Timing entries страницы (пассивно, без изменения запросов); query-параметры, похожие на токены/секреты/идентификаторы сессии, маскируются.

События буферизуются в памяти и выгружаются одним JSON. Вызовы `onDrawing` не логируются каждый кадр: событие создаётся только при изменении количества/последней координаты точек.

## Ограничения прототипа

- Это диагностический DevTools-snippet, а не расширение браузера и пока не интеграция с AutoDraw.
- Он не управляет мышью, кистью, сетью или состоянием доски.
- В игровом bundle установлен источник индикатора CHALK: `BoardPane.updateLess()` считает точки `atom.points`, вычисляет `less = max - pointCount` и отправляет `percent = less / max`. Это квота игровых точек, а не площадь краски или длина пути. Сам Monitor 0.1.2 не экспортирует `BoardPane.max` и `BoardPane.less`, поэтому его JSON пока не содержит прямого значения остатка CHALK. Анализ изменённых пикселей остаётся отдельной метрикой геометрии.
- Resource Timing показывает завершённые ресурсные операции, но не доказывает отсутствие всех типов сетевой активности. Он не перехватывает и не меняет fetch/XHR.
- Автопоиск зависит от доступности Egret stage и структуры display list. Если объект не найден, нельзя считать монитор подключённым.
- В семи сохранённых Monitor JSON для горизонтальных/вертикальных серий указаны `boardDetected=true`, `droppedEvents=0`, `errors=0`. Это подтверждает работу сбора событий в тех прогонах, но не подтверждает отсутствие влияния на FPS, корректность attach/detach и полноту привязки к манифестам. В этих семи манифестах `game_monitor_report_path` не заполнен.
- Нельзя использовать результаты для калибровки или считать влияние Monitor нулевым до проверки координат и сравнения с запуском без Monitor.


Дополнительно: во время активного штриха Monitor опрашивает компактный снимок `atom.points` с интервалом 25 мс и создаёт событие только при изменении количества/последней координаты. Это сделано потому, что Egret мог зарегистрировать ссылку на `onDrawing` как listener до установки обёртки; замена свойства экземпляра в таком случае не перехватит ранее сохранённую ссылку на функцию. Опрос работает только между `onDrawStart` и `onDrawingEnd`, а не постоянно.


Для определения окна активного ввода прототип также слушает `pointerdown`, `pointerup` и `pointercancel` в capture-фазе, только если событие пришло с HTML canvas. Эти события помечаются как `*_CANDIDATE`: canvas может содержать и элементы интерфейса, поэтому сам pointerdown не считается доказательством рисования. Изменения `atom.points` в этом интервале дают подтверждение фактической активности доски. Все обработчики удаляются при `stop()`.
\n\n## Защита выгрузки\n\nMonitor 0.1.2 маскирует значения query-параметров, чьи имена содержат `token`, `auth`, `session`, `cookie`, `secret`, `key` или `uid`/`user`, в URL Resource Timing. Не публикуйте сырые сетевые журналы и проверяйте экспорт перед передачей.\n

## Уточнение по CHALK и границам пассивности — 31 октября 2026 г.

Игровой bundle анализировался отдельно, без исполнения. Точная формула внутреннего счётчика: `less = max - количество точек atom.points`; UI получает долю `less / max`. Точки добавляются в игровом цикле `ENTER_FRAME`, только если координата внутри доски и отличается от предыдущей. Поэтому длина пути и число точек не взаимозаменяемы; скорость указателя влияет на sampling.

Monitor 0.1.2 сохраняет `pointCount`, но не `max/less`. Для прямого CHALK-снимка текущего JSON недостаточно. Кроме того, `attach()` временно заменяет методы BoardPane обёртками, а polling и wrappers выполняют дополнительные полные обходы `atom.points`. Влияние на производительность и восстановление оригинальных descriptors ещё не проверены.

CI проверяет JavaScript Monitor только командой `node --check`; поведенческих JS-тестов жизненного цикла Monitor пока не найдено. Python tests в `tests/test_websocket_smoke_server.py` проверяют только отдельный transport smoke server.
