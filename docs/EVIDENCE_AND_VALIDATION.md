# Доказательства, проверки и уровни подтверждения

**Статус:** ACTIVE — постоянный стандарт доказательности  
**Назначение:** единый язык для утверждений о коде, тестах, CI, сборках, runtime и экспериментах.

## 1. Основное правило

Формулировка вывода не должна быть сильнее подтверждающего его доказательства. Всегда указывать, что проверялось, на каком commit, каким способом, где результат и что осталось непроверенным.

### 1.1. Границы локальной проверки и live-доказательств

Запущенная локальная программа, игровая браузерная сессия и реальная доска доступны только пользователю; live-тесты в этой среде может непосредственно выполнить только пользователь. Локальная рабочая копия Git и её фактический `git status` также доступны только пользователю. Проверка GitHub branch/commit/files/Actions не подтверждает локальное состояние ПК. Для E4 требуются результаты, переданные пользователем: идентификаторы запуска/сессии, первичные captures, runtime logs и прочие предусмотренные протоколом evidence. Без них статус live-проверки — NOT_RUN, BLOCKED или UNKNOWN по фактической причине, но не PASS.

Для тестов взаимодействия с игровой доской обязательна стратегия максимальной автоматизации: повторное использование существующих harness/Monitor/Bridge/executor/capture/analyzer и создание недостающих средств в разрешённом объёме. Автоматизация должна уменьшать ручные операции, сохранять raw evidence и связывать результат с конкретным run. Она не означает удалённый доступ ИИ к локальной среде и не заменяет пользовательское выполнение локальной части теста.

## 2. Уровни доказательности

| Уровень | Тип | Допустимое утверждение | Не доказывает |
|---|---|---|---|
| E0 | Гипотеза | Есть проверяемое предположение | Подтверждённое поведение |
| E1 | Статический анализ | Конструкция/связь есть в исходниках конкретной версии | Работу в runtime |
| E2 | Тесты | Указанные тесты прошли на конкретном состоянии | Непокрытые сценарии |
| E3 | CI/build | Указанные jobs/workflow успешны на конкретном commit | Полную корректность продукта или live-сценария |
| E4 | Runtime/live | Сценарий наблюдался в целевой среде с артефактами | Универсальность вне условий проверки |
| E5 | Независимая validation | Первичные данные проверены отдельным анализатором/аудитом в заявленной области | Применимость вне валидированного domain |

Уровни описывают тип подтверждения, а не общую оценку качества. E5 не гарантирует статистическую репрезентативность.

## 3. Подтверждение по типам

**E1:** путь/символ/участок кода, commit SHA, связи и ограничения статического вывода.

**E2:** точная команда/test selector, среда и параметры, passed/failed/skipped/warnings, commit и лог при наличии. Различать unit, integration, regression, contract, property, UI и synthetic tests.

**E3:** GitHub Actions run URL/ID, проверенный commit SHA, workflow и отдельные jobs, skipped jobs, artifact name/ID/URL и срок хранения. Полный CI PASS допустим только после завершения workflow и всех обязательных jobs. Не переносить PASS с предыдущего commit.

**E4:** целевая среда и версия приложения, настройки/профиль/калибровка, task/session/run IDs, входные и выходные данные, ошибки, логи, screenshots/PNG и ручные отклонения от процедуры.

**E5:** frozen inputs и hashes, независимость анализатора (где применимо), accepted/rejected/missing counts, метрики/формулы, целостность данных, версия анализатора и область применимости.

## 4. Статусы проверки

- NOT_RUN — не запускалось.
- PASS — выполнено и прошло.
- FAIL — выполнено и не прошло.
- PARTIAL — часть проверок завершена.
- BLOCKED — запуск невозможен по указанной причине.
- SKIPPED — намеренно пропущено с причиной.
- UNKNOWN — данных недостаточно или они недоступны.

Не заменять их общим словом «проверено».

## 5. Формулировки

Корректно: «Тесты A и B прошли на commit X; C пропущен». «Workflow N завершился success на X; jobs A/B успешны, benchmark skipped». «Сценарий выполнен в Windows/browser session N, приложены before/after PNG и runtime logs». «45/45 samples приняты независимым analyzer; вывод ограничен испытанными геометриями».

Некорректно: «Функция работает» при наличии только unit test; «CI PASS» при workflow in progress; «радиус не влияет» при ограниченной матрице; «алгоритм оптимален» при сравнении нескольких кандидатов; «live прошёл» при наличии только synthetic fixtures или startup smoke-test.

## 6. Метрики

Для каждой метрики указывать определение, единицы, формулу, источник, округление, обработку пропусков/выбросов и неопределённость. Не смешивать геометрическую длину пути, координаты, игровые точки, площадь покрытия и расход ресурса без доказанной связи. Недоступное точное значение обозначать unavailable/unknown, а не подменять estimate.

## 7. Происхождение данных

Для доказательных наборов сохранять raw data без перезаписи, стабильный ID, hash, версию схемы, источник/время, commit/конфигурацию, версию анализатора и журнал преобразований. Derived data не заменяет raw data. Если первичный артефакт недоступен, сообщить об этом.

## 8. Отрицательные и неполные результаты

Не скрывать failed/rejected samples. Для каждого отклонения фиксировать причину и влияние. Не менять acceptance criteria после просмотра результатов ради получения PASS. Изменение критериев требует новой версии протокола.

## 9. Область применимости

Ограничивать вывод проверенными версиями/commit, входными данными, конфигурациями, диапазонами параметров, средой, числом повторов и выборкой. Непроверенные комбинации — UNKNOWN/NOT VALIDATED. Экстраполяцию можно указать как гипотезу, но не как факт.

## 10. Карточка проверки

| Поле | Значение |
|---|---|
| Проверка | Что проверялось |
| Уровень | E1–E5 |
| Статус | PASS/FAIL/PARTIAL/BLOCKED/NOT_RUN/SKIPPED/UNKNOWN |
| Commit | Полный SHA |
| Метод | Команда/workflow/runtime procedure/analyzer |
| Результат | Количественные итоги |
| Evidence | Ссылки на logs/artifacts/data/report |
| Ограничения | Что не проверено |
| Следующий шаг | Если нужен |
